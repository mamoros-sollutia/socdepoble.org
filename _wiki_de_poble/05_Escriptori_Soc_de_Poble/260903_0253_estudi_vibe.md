## 1. Diagnòstic · Origen del trencament CSS/DOM

### Veredicte principal: **`NotesSection.css` és INEXISTENT**

Aquest és el cor del problema. La cadena d'evidència:

1. `NotesSection.jsx` (línia 12) declara:
   ```js

   ```
2. Aquest fitxer **no apareix** en el bundle d'auditoria ni es troba cap definició de les seues classes enlloc del `index.css` global.
3. Anàlisi d'ocurrències dins del CSS global subministrat:

   | Classe de layout | Definicions pròpies a `index.css` |
   |---|---|
   | `.notes-shell` | 0 (només 1 selector `:has()` que l'**assumeix** existent) |
   | `.notes-column` | **0** |
   | `.notes-column--left` / `--middle` / `--editor` | **0** |
   | `.editor-toolbar` | **0** |
   | `.mobile-panel-*` | **0** |
   | `.editor-scroll-area` | **0** |
   | `.editor-tiptap-container` | **0** |
   | `.notes-list-actions` / `.notes-list-container` | **0** |
   | `.notes-column__body` / `__scroll` | **0** |
   | `.folders-list` / `.folder-item` | **0** |

**Conclusió mecànica:** totes les classes que donen estructura al component — l'esquelet de 3 columnes, l'amplada de cada columna, l'alçada plena (`height:100%`), la distribució `flex`, els estats de col·lapse, els panells mòbils, la barra d'eines de l'editor — **no tenen cap regla CSS que les defineixi**.

### Com es manifesta el "desmontatge"

Sense `NotesSection.css`, el navegador aplica la cascada per defecte:

- `.notes-shell` és un `<article>` de block-flow normal: **no és flex ni grid**, no té `height`, no té `display:flex`.
- Els tres `<section class="notes-column">` (Sidebar, List, Editor) es renderitzen com a **blocs apilats verticalment**, cada un amb `width:100%` automàtic i alçada de contingut (no plena).
- `mobile-panel-${mobilePanel}` no té cap efecte perquè cap regla llegeix aquesta classe.
- `.editor-scroll-area`, `.editor-tiptap-container` queden sense `overflow`, sense `flex:1`.
- Les columnes col·lapsades (`.collapsed`) no es contreuen perquè no hi ha `flex-basis: 0` ni `overflow:hidden`.

Resultat: les tres columnes es "desmunten" en una pila vertical descontrolada. **Aquest és, mecànicament, el 100% del problema de maquetació.**

### Evidència secundària

L'únic CSS de `index.css` que toca el component és un override en línia 3711:
```css
.app-main__content article.card:has(.notes-shell) {
  padding: 0; overflow: hidden;
}
```
Aquesta regla **assumeix** que `.notes-shell` ja té el seu layout propi (en `NotesSection.css`). Com que aquest no existeix, l'override opera sobre el buit.

### Possibles causes de l'absència

- El fitxer `NotesSection.css` fou creat en una sessió anterior i **mai commitat** (treball local perdut).
- Una operació de migració/el·liminació (ex. `scripts/migrate-component.sh`) l'eliminà sense substituir-lo.
- Una IA en una sessió prèvia reféu el component JSX però **ometé** regenerar el CSS (possible eco de l'incident de plantilla).

## 3. Normalització d'icones · Veredicte sincer

### 3.1 Diagnòstic verificat

La barra de format (`NotesToolbar.jsx`) importa:
```js
import { ArrowLeft, Heading2, List, Bold, Italic, Strikethrough, Globe } from 'lucide-react';
```
**Verificat contra lucide.dev:** totes aquestes icones existeixen i pertanyen a `lucide-react`. El Mestre té raó que totes són de Lucide — la sensació de "col·leccions diferents" és **incorrecta com a fet**, però **comprensible com a percepció**, i ací explica per què.

### 3.2 Per què pareixen "lletres antigues"

Les icones d'edició de text de Lucide (`Bold`, `Italic`, `Strikethrough`, `Heading2`) **són, per disseny, glifs de lletra**: el camí SVG traça una "B" en negreta, una "I" en cursiva, una "S" ratllada i un "H2". Això és una decisió conscient del disseny de Lucide (confirmat a la pàgina de cada icona i a l'issue #363 del repositori, on la comunitat debat exactament això).

> **Veritat incòmoda:** dins del catàleg de Lucide **no existeixen alternatives de línia geomètrica pura** per a Negreta / Cursiva / Ratllat. Aquestes accions es representen convencionalment amb glifs de lletra a Lucide (i a quasi tots els kits d'icones: Phosphor, Heroicons, Tabler…). No hi ha un `Bold` "geomètric" a Lucide perquè no és així com Lucide modela l'acció.

### 3.3 Recomanació (honestament dividida en opcions)

**Opció A — Recomanada · Coherència sense mentir el sistema**
- Mantindre `Bold`, `Italic`, `Strikethrough`, `Heading2` (són l'estàndard de Lucide).
- Corregir la incoherència visual **real**, que no és la col·lecció sinó la renderització:
  - Unificar `size={18}` en **tots** els botons (ja està a 18 ✓ — verificar que cap override el canvia).
  - Unificar `strokeWidth` implícit (Lucide per defecte = 2; no barrejar amb icones a `strokeWidth={1.5}`).
  - Assegurar que el color ve de `currentColor` (la barra ja és fosca: `var(--sdp-sobre-roca)`).
- Això resol la sensació d'"estil antic" perquè la incoherència venia dels glifs renderitzats a mides/trams diferents, no de la col·lecció.

**Opció B — Si el Mestre insisteix en glifs no-lletra**
- Caldrà dibuixar **SVG propis** per a 3-4 botons (Negreta = un rectangle ple, Cursiva = una línia obliqua, Ratllat = una línia horitzontal, H2 = dues línies amb marca).
- **Advertiment:** això trenca la regla "tot Lucide excepte la IAIA" i afegeix un deute de manteniment. Es documenta al `.design-guard-deute.json` si s'adopta.

**Opció C — Compromís defensable**
- Negreta → `Bold` (llest); Cursiva → `Italic`; Ratllat → `Strikethrough`.
- H2 → substituir `Heading2` per `Heading` (glif "H" genèric, més neutre que "H2") i indicar el nivell amb un `aria-label` o text adjacent. Redueix la "antiguitat" percebuda del glif "H2" sense eixir de Lucide.

La meua recomanació al Consell: **Opció A**, per honestedat tècnica. Si el Mestre hi persisteix, **Opció C** com a pas intermedi abans de tocar SVG propi.

## 4. Protocol d'autocorrecció · Protecció de la PLANTILLA_ISO_SDP

### 4.1 L'incident

Una IA generà un prompt produint un document **esborrant el format** de `PLANTILLA_ISO_SDP.md` sense haver llegit el context de la Wiki. Cal un mecanisme que ho **impedeixi mecànicament**, no per bona voluntat.

### 4.2 Anàlisi de la plantilla

La `PLANTILLA_ISO_SDP.md` té una estructura fixa i recognoscible:
- Frontmatter YAML amb `tipus`, `estat`, `description`, `aliases`.
- Blocs obligatoris: **Font de Logos**, **Bloc Fixe d'Identitat**, **Objectiu**, **Context Necessari**, **Instrucció Principal**, **Output Esperat**.
- Blocs condicionals `[IF:tipus=...]`.
- **Tancament Obligatori** + **Sinapsis** + **Taxonomia** + **Ancoratge de Seguretat** + **Sinapsis Entrants (Autogenerat)**.

Aquests blocs són la "signatura" de la plantilla. El protocol els protegeix com a **marca d'aigua estructural**.

### 4.3 Protocol `PROTOCOL_GUARDIA_PLANTILLA`

**Precondicions**
- El directori `plantilles/` conté `PLANTILLA_ISO_SDP.md` i altres plantilles canòniques.
- Existeix un hash/fingerprint de cada plantilla canònica (el `MANIFEST` del bundle ja porta `sha256` per fitxer — es pot reutilitzar).

**Procediment** — s'executa com a **preflight hook** abans de qualsevol escriptura d'un document de tipus `petorreta`, `prompt`, `informe`, `acta`, `protocol`, `skill`, `plantilla`:

1. **Detecció d'origen.** Quan una IA o un procés genera un document nou, el hook inspecciona el frontmatter `tipus`. Si el tipus és un dels que deriva de `PLANTILLA_ISO_SDP`, continua al pas 2. Si no, deixa passar.

2. **Lectura obligatòria (read-before-write).** Abans d'escriure, el procés **ha d'haver llegit** el fitxer de plantilla corresponent (o el `00_INDEX` / context de la Wiki). El hook comprova que la plantilla canònica apareix al log de fitxers llegits de la sessió. Si no hi és → **BLOQUEIG** amb missatge:
   > `GUARDIA_PLANTILLA: refusa l'escriptura. Has de llegir PLANTILLA_ISO_SDP.md (o l'índex de la Wiki) abans de generar un document tipus={tipus}.`

3. **Verificació de signatura.** El document generat ha de contindre **tots els blocs obligatoris** de la plantilla. El hook cerca per text fixe:
   - `## Font de Logos`
   - `## Bloc Fixe d'Identitat`
   - `## Objectiu`
   - `## Context Necessari`
   - `## Instrucció Principal`
   - `## Output Esperat`
   - `## Tancament Obligatori`
   - `## Sinapsis`
   - `## Taxonomia`
   - `Ancoratge de Seguretat`
   Si en falta algun → **BLOQUEIG** i llista els blocs absents.

4. **Verificació de frontmatter.** El `tipus` ha de ser un dels valors permesos (`document|index|norma|protocol|registre|skill|plantilla|acta|informe|prompt|petorreta`). `estat` no pot ser `canonic` (només decisió humana). Si viola → **BLOQUEIG**.

5. **Detecció d'esborrat de format.** Si el document **no** conté cap dels blocs obligatoris però el `tipus` indica que hauria de derivar de plantilla → és el senyal de l'incident ("esborrar el format sense llegir la Wiki"). Es registra al `LEDGER.md` com a **intent bloquejat** i s'avisa el Consell.

6. **Reparació automàtica (no destructiva).** Si el document té la majoria de blocs però n'hi falten 1-2, el hook **no reescriu** el document; en lloc d'això retorna un avís amb els blocs que cal afegir i el seu text canònic, perquè l'autor (humà o IA) els afegisca manualment. Mai injecta contingut automàticament.

**Criteri d'èxit**
```
EXIT: Cap document tipus derivat de plantilla s'escriu sense contenir els blocs obligatoris, ni sense que la plantilla canònica haja sigut llegida prèviament en la sessió.
```

### 4.4 Implementació tècnica (integració amb el sistema existent)

El sistema ja té `.agents/hooks/verify.mjs` (preflight) i `.agents/hooks/preflight_matrix_wrapper.mjs`. El protocol s'implementa com una **funció exportada** dins de `verify.mjs` o com un nou mòdul `verify_plantilla.mjs`:

```js
// .agents/hooks/verify_plantilla.mjs (esquema)
import { readFileSync, existsSync } from 'node:fs';

const BLOCS_OBLIGATORIS = [
  '## Font de Logos',
  '## Bloc Fixe d'Identitat',
  '## Objectiu',
  '## Context Necessari',
  '## Instrucció Principal',
  '## Output Esperat',
  '## Tancament Obligatori',
  '## Sinapsis',
  '## Taxonomia',
];

const TIPUS_DERIVATS = new Set(['petorreta','prompt','informe','acta','protocol','skill','plantilla','norma','registre']);

export function verificaPlantilla({ rutaOutput, contingut, fitxersLlegits }) {
  // 1. extreure frontmatter
  const fm = extreuFrontmatter(contingut);
  if (!fm || !TIPUS_DERIVATS.has(fm.tipus)) return { ok: true }; // no aplica

  // 2. read-before-write
  const llegitPlantilla = fitxersLlegits.some(p => /PLANTILLA_ISO_SDP/.test(p))
    || fitxersLlegits.some(p => /00_INDEX/.test(p));
  if (!llegitPlantilla) {
    return { ok: false, error: 'GUARDIA_PLANTILLA: cal llegir PLANTILLA_ISO_SDP.md o l\\'índex de la Wiki abans d\\'escriure tipus=' + fm.tipus };
  }

  // 3. signatura de blocs
  const absents = BLOCS_OBLIGATORIS.filter(b => !contingut.includes(b));
  if (absents.length === BLOCS_OBLIGATORIS.length) {
    return { ok: false, error: 'GUARDIA_PLANTILLA: format esborrat (0 blocs). Possible incident.', critical: true };
  }
  if (absents.length > 0) {
    return { ok: false, error: 'GUARDIA_PLANTILLA: falten blocs: ' + absents.join(', '), warnings: absents };
  }

  // 4. frontmatter
  if (fm.estat === 'canonic') {
    return { ok: false, error: 'GUARDIA_PLANTILLA: estat=canonic requereix decisió humana.' };
  }
  return { ok: true };
}
```

El `preflight_matrix_wrapper.mjs` l'invoca abans de permetre l'escriptura. Els intents bloquejats s'apunten al `.agents/LEDGER.md`.

### 4.5 Per què això hauria aturat l'incident

L'incident consistí a generar un prompt sense el format de plantilla. Amb el pas 2 (read-before-write) i el pas 3 (signatura de blocs), el procés hauria estat **bloquejat** abans de l'escriptura perquè: (a) la plantilla no constava com a llegida, i (b) el resultat no contenia cap bloc obligatori.
