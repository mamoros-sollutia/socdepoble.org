## 1. RECONEIXEMENT DEL TERRENY (Estat Actual)

He inspeccionat els plans del bundle. L'arquitectura actual té **bons fonaments de pedra**, però amb alguns murs mitgers que calen completar:

### 1.1. Fortaleses existents
- **Supabase Auth (GoTrue)** ja gestiona usuaris amb JWT i RLS.
- **Taula `profiles`** està vinculada a `auth.users` via trigger `handle_new_user()`.
- **Taula `organizations`** suporta 4 tipus: `company`, `group`, `entity`, `city_hall`.
- **Taula `organization_memberships`** ja té rols (`owner`, `admin`, `member`) i trigger de protecció del darrer propietari (`sdp_protegeix_propietari`).
- **Funcions RPC** com `create_organization` i `list_my_organizations` ja operen amb `security invoker`.
- **Frontend**: `PerfilContext` ja gestiona `currentIdentity`, `organizations`, i `switchIdentity`. El routing `/jo/*` i `/e/:slug/*` està llest.

### 1.2. Bresques estructurals a tapar
1. **No existeix el rol de Superadministrador** del sistema (nivell global, per sobre de town).
2. **No hi ha mecanisme de reclamació** d'entitats ja existents (només es poden crear noves).
3. **L'onboarding** està encadenat a 3 passos rígids (Registre → Empresa Sóc de Poble → Grup Rentonar). No permet escollir lliurement tipus d'entitat ni saltar-se la cadena.
4. **No hi ha taula de sol·licituds pendents** per a entitats orfes (ajuntaments, associacions preexistents).
5. **El registre per email** no distingeix clarament entre entorn de desenvolupament (confirmació automàtica) i producció (confirmació per correu).

### 2.1. Nova taula: `system_roles` (Rols globals)

```sql
-- Rols del sistema, per damunt de town/organització
create table if not exists public.system_roles (
  user_id uuid primary key references auth.users(id) on delete cascade,
  role text not null check (role in ('superadmin', 'moderator', 'support')),
  granted_by uuid references auth.users(id) on delete set null,
  granted_at timestamptz not null default now(),
  revoked_at timestamptz
);

create index if not exists idx_system_roles_active
  on public.system_roles(role)
  where revoked_at is null;

-- Funció helper per comprovar superadmin
create or replace function private.is_superadmin()
returns boolean
language sql
stable
security definer
set search_path = ''
as $$
  select exists (
    select 1 from public.system_roles
    where user_id = (select auth.uid())
      and role = 'superadmin'
      and revoked_at is null
  );
$$;

-- RLS: només superadmins poden veure/gestionar rols globals
alter table public.system_roles enable row level security;

create policy "system_roles_select_own"
  on public.system_roles for select
  using (user_id = (select auth.uid()));

create policy "system_roles_superadmin_all"
  on public.system_roles for all
  using ((select private.is_superadmin()))
  with check ((select private.is_superadmin()));
```

### 2.2. Nova taula: `entity_claims` (Reclamacions d'entitats)

```sql
-- Permet a un usuari sol·licitar la propietat d'una entitat existent
create table if not exists public.entity_claims (
  id uuid primary key default gen_random_uuid(),
  organization_id uuid not null references public.organizations(id) on delete cascade,
  claimant_user_id uuid not null references auth.users(id) on delete cascade,
  claimant_email text not null, -- per contacte extern si cal
  claimant_name text not null,
  document_url text, -- enllaç a document acreditatiu (escrit, acta, etc.)
  status text not null default 'pending' check (status in ('pending', 'approved', 'rejected', 'expired')),
  reviewed_by uuid references auth.users(id) on delete set null,
  reviewed_at timestamptz,
  rejection_reason text,
  created_at timestamptz not null default now(),
  expires_at timestamptz not null default (now() + interval '30 days'),
  unique (organization_id, claimant_user_id, status)
);

create index if not exists idx_entity_claims_org
  on public.entity_claims(organization_id, status);

create index if not exists idx_entity_claims_claimant
  on public.entity_claims(claimant_user_id, status);

-- RLS
alter table public.entity_claims enable row level security;

create policy "entity_claims_select_own"
  on public.entity_claims for select
  using (claimant_user_id = (select auth.uid()) or (select private.is_superadmin()));

create policy "entity_claims_insert_own"
  on public.entity_claims for insert
  with check (claimant_user_id = (select auth.uid()));

create policy "entity_claims_superadmin_update"
  on public.entity_claims for update
  using ((select private.is_superadmin()));
```

### 2.3. Nova funció RPC: `claim_organization`

```sql
create or replace function public.claim_organization(
  p_organization_id uuid,
  p_claimant_email text default null,
  p_claimant_name text default null,
  p_document_url text default null
)
returns jsonb
language plpgsql
security invoker
set search_path = ''
as $$
declare
  v_user_id uuid := (select auth.uid());
  v_org record;
begin
  if v_user_id is null then
    raise exception 'Cal iniciar sessió.' using errcode = '42501';
  end if;

  select id, tenant_id, name, slug, kind into v_org
  from public.organizations
  where id = p_organization_id;

  if not found then
    raise exception 'L’entitat no existeix.' using errcode = '22023';
  end if;

  -- Comprovar que l'entitat no té ja un owner
  if exists (
    select 1 from public.organization_memberships
    where organization_id = p_organization_id and role = 'owner'
  ) then
    raise exception 'Aquesta entitat ja té propietària.' using errcode = '23505';
  end if;

  -- Comprovar que no hi ha una reclamació pendent d'aquest usuari
  if exists (
    select 1 from public.entity_claims
    where organization_id = p_organization_id
      and claimant_user_id = v_user_id
      and status = 'pending'
  ) then
    raise exception 'Ja tens una reclamació pendent per a aquesta entitat.' using errcode = '23505';
  end if;

  insert into public.entity_claims (
    organization_id,
    claimant_user_id,
    claimant_email,
    claimant_name,
    document_url
  ) values (
    p_organization_id,
    v_user_id,
    coalesce(p_claimant_email, (select auth.jwt() ->> 'email')),
    coalesce(p_claimant_name, (select full_name from public.profiles where id = v_user_id)),
    p_document_url
  );

  return jsonb_build_object(
    'status', 'pending',
    'message', 'Reclamació enviada. Un administrador la revisarà.'
  );
end;
$$;
```

### 2.4. Nova funció RPC: `approve_claim` (només superadmin)

```sql
create or replace function public.approve_claim(
  p_claim_id uuid,
  p_approved boolean,
  p_reason text default null
)
returns jsonb
language plpgsql
security invoker
set search_path = ''
as $$
declare
  v_claim record;
  v_reviewer uuid := (select auth.uid());
begin
  if not (select private.is_superadmin()) then
    raise exception 'Necessites permís de superadministrador.' using errcode = '42501';
  end if;

  select * into v_claim from public.entity_claims where id = p_claim_id;
  if not found then
    raise exception 'Reclamació no trobada.' using errcode = '22023';
  end if;

  if v_claim.status <> 'pending' then
    raise exception 'La reclamació ja ha sigut tractada.' using errcode = '23505';
  end if;

  update public.entity_claims
  set status = case when p_approved then 'approved' else 'rejected' end,
      reviewed_by = v_reviewer,
      reviewed_at = now(),
      rejection_reason = case when not p_approved then p_reason else null end
  where id = p_claim_id;

  if p_approved then
    -- Assignar com a owner de l'organització
    insert into public.organization_memberships (
      organization_id, tenant_id, user_id, role
    )
    select v_claim.organization_id, o.tenant_id, v_claim.claimant_user_id, 'owner'
    from public.organizations o
    where o.id = v_claim.organization_id
    on conflict (organization_id, user_id) do update set role = 'owner';
  end if;

  return jsonb_build_object(
    'status', case when p_approved then 'approved' else 'rejected' end,
    'organization_id', v_claim.organization_id
  );
end;
$$;
```

```javascript
import { useState, useEffect } from 'react';
import { supabase } from '../data/supabaseBackend.js';

export function useSystemRole() {
  const [isSuperAdmin, setIsSuperAdmin] = useState(false);
  const [loading, setLoading] = useState(true);

  useEffect(() => {
    let cancelled = false;
    async function check() {
      try {
        const { data, error } = await supabase.rpc('is_superadmin');
        if (!cancelled) setIsSuperAdmin(!!data && !error);
      } catch {
        if (!cancelled) setIsSuperAdmin(false);
      } finally {
        if (!cancelled) setLoading(false);
      }
    }
    check();
    return () => { cancelled = true; };
  }, []);

  return { isSuperAdmin, loading };
}
```

## 4. FLUXOS D'USUARI

### 4.1. Registre d'usuari normal

```
1. Usuari entra a /connectar
2. Omple email + contrasenya + RGPD (o Google OAuth)
3. Backend: auth.users creat → trigger handle_new_user() → profiles creat
4. Frontend: rep access_token (dev) o missatge de confirmació (prod)
5. Si té sessió: redirigeix a Onboarding amb Pas 1 (IdentityFork)
```

### 4.2. Assignació de Superadministrador

```
1. Desenvolupador/DBA executa manualment:
   insert into system_roles (user_id, role, granted_by) 
   values ('uuid-del-mestre', 'superadmin', 'uuid-del-mestre');
   
2. O via script de migració amb segell SDP.

3. No hi ha UI pública per a açò (per seguretat).
```

### 4.3. Reclamació d'entitat (Ajuntament, Associació preexistent)

```
1. Entitat creada prèviament (per seed o per superadmin) sense owner.
2. Usuari navega a /connectar → "Vull gestionar un ajuntament..."
3. Frontend crida claim_organization(organization_id)
4. Backend: insert a entity_claims (status: pending)
5. Superadmin rep notificació (futur: via UI de control)
6. Superadmin crida approve_claim(id, true)
7. Backend: actualitza claim + insert a organization_memberships com owner
8. Usuari rep notificació d'aprovació (futur: via email o UI)
```

## 6. MURALLES DE SEGURETAT I RGPD

| Risc | Contramesura |
|---|---|
| **Usurpació d'entitat** | Reclamació requereix aprovació manual de superadmin + document acreditatiu opcional. |
| **Superadmin no controlat** | Creació només per SQL directe o script versionat. No hi ha UI pública. |
| **Fuga de dades de reclamacions** | RLS a `entity_claims`: només el claimant i superadmin poden veure les files. |
| **RGPD Llei 05** | El perfil segueix sent `visibility = 'private'` per defecte. Les reclamacions no exposen dades personals a tercers. |
| **SDP-LOCK** | Si una migració falla, el trigger `sdp_protegeix_propietari` impedeix deixar entitats sense owner. |

## 8. TANCAMENT

Aquest pla no introdueix **cap dependència nova** (ni npm ni servei extern). Tot es construeix sobre el pedestal existent de Supabase Auth + PostgreSQL. Les mutacions són quirúrgiques: tres taules noves, dues funcions RPC, i un refactor de l'onboarding que manté els 3 passos originals però els desencadena amb un **bifurcador d'identitat**.

La metàfora del Mas ho diu clar: abans deixàvem que tot el món entrara pel mateix portal. Ara hem construït tres portes: una per a qui ve a fundar, una altra per a qui ve a reclamar el que ja és seu, i una tercera per a qui només vol mirar. I damunt de tot, una torre de vigilància (superadmin) que obri i tanque les portes amb clau.
