## 1. Anàlisi de l'Estat Actual

### 1.1 Arquitectura Front-end d'Identitats
El front-end ja està refactoritzat amb dos contextos clau:

- **`IdentitatContext.jsx`**: Detecta automàticament el tipus d'actor segons la ruta:
  - `/jo/*` → `actorType = 'persona'`, `actorId = currentUser.id`
  - `/e/:slug/*` → `actorType = 'entitat'`, `actorId = slug`
  - Exposa `actorKey = ${actorType}::${actorId}`

- **`SessionContext.jsx`**: Gestió de sessió via `getCurrentUser()` i event `sdp:auth-change`

- **`backendPort.js`**: Adaptador d'abstracció que defineix la interfície que qualsevol backend ha d'implementar:
  - Auth: `registerWithEmail`, `loginWithEmail`, `loginWithGoogle`, `logout`, `getCurrentUser`
  - Organitzacions: `listMyOrganizations`, `createOrganization`, `updateOrganization`
  - Perfil: `getProfile`, `updateProfile`, `updateUserPassword`

### 1.2 Esquema Supabase Existent
L'esquema actual (`supabase/schema.sql`) ja conté la major part de l'estructura necessària:

| Taula | Propòsit |
|---|---|
| `auth.users` | Gestió per Supabase GoTrue (email/password, OAuth, JWT) |
| `public.profiles` | Perfil públic extendit (FK → auth.users). **Sempre `visibility = 'private'`** |
| `public.organizations` | Entitats: `kind ∈ {company, group, entity, city_hall}` |
| `public.organization_memberships` | Relació usuari-entitat amb `role ∈ {owner, admin, member}` |
| `public.towns` / `town_memberships` | Tenant/poble i pertinença |

**Triggers automàtics existents:**
- `on_auth_user_created` → `handle_new_user()`: Crea `public.profiles` automàticament en registrar-se
- `trg_organization_add_owner` → `private.add_organization_owner()`: El creador d'una organització es converteix en `owner` automàticament
- `sdp_protegeix_propietari`: SDP-LOCK — Impedeix eliminar l'últim `owner` d'una organització

## 2. Esquema SQL Refinat per a la Fase 3

L'esquema existent és sòlid. Cal afegir els elements mancants per completar la Fase 3:

### 2.1 Afegits Proposats

```sql
-- ============================================================
-- FASE 3: EXTENSIONS DE L'ESQUEMA EXISTENT
-- Aplicar sobre supabase/schema.sql existent
-- ============================================================

-- ------------------------------------------------------------
-- 2.1.1 Taula de rols globals de plataforma (Superadministrador)
-- ------------------------------------------------------------
create table if not exists public.platform_roles (
  user_id uuid primary key references auth.users(id) on delete cascade,
  role text not null check (role in ('superadmin')),
  granted_by uuid references auth.users(id) on delete set null,
  granted_at timestamptz not null default now()
);
alter table public.platform_roles enable row level security;
revoke all on table public.platform_roles from anon, authenticated;

-- Només superadmin pot llegir/escriure. Funció helper per comprovar.
create or replace function private.is_superadmin()
returns boolean
language sql stable security definer set search_path = ''
as $$
  select (select auth.uid()) is not null and exists (
    select 1 from public.platform_roles
    where user_id = (select auth.uid()) and role = 'superadmin'
  );
$$;
revoke execute on function private.is_superadmin() from public, anon;
grant execute on function private.is_superadmin() to authenticated;

-- ------------------------------------------------------------
-- 2.1.2 Taula de reclamacions de propietat d'entitats
-- Quan una persona reclama ser el legítim representant d'una
-- organització ja existent (empresa, ajuntament, associació).
-- ------------------------------------------------------------
create table if not exists public.entity_ownership_claims (
  id uuid primary key default gen_random_uuid(),
  organization_id uuid not null,
  tenant_id uuid not null,
  claimant_user_id uuid not null references auth.users(id) on delete cascade,
  evidence text not null check (char_length(btrim(evidence)) between 10 and 2000),
  status text not null default 'pending' check (status in ('pending', 'approved', 'rejected')),
  reviewed_by uuid references auth.users(id) on delete set null,
  reviewed_at timestamptz,
  reviewer_note text check (char_length(coalesce(reviewer_note, '')) <= 500),
  created_at timestamptz not null default now(),
  foreign key (tenant_id, organization_id)
    references public.organizations(tenant_id, id) on delete cascade,
  unique (organization_id, claimant_user_id)
);
alter table public.entity_ownership_claims enable row level security;
revoke all on table public.entity_ownership_claims from anon;

-- RLS per a reclamacions
grant select, insert on table public.entity_ownership_claims to authenticated;
grant update (status, reviewed_by, reviewed_at, reviewer_note) on table public.entity_ownership_claims to authenticated;

drop policy if exists "claimant read own claims" on public.entity_ownership_claims;
create policy "claimant read own claims" on public.entity_ownership_claims
for select to authenticated using (
  claimant_user_id = (select auth.uid())
  or (select private.can_manage_organization(organization_id))
  or (select private.is_superadmin())
);

drop policy if exists "claimant insert own claim" on public.entity_ownership_claims;
create policy "claimant insert own claim" on public.entity_ownership_claims
for insert to authenticated with check (
  claimant_user_id = (select auth.uid())
  and status = 'pending'
  and exists (select 1 from public.town_memberships where town_id = tenant_id and user_id = (select auth.uid()))
);

drop policy if exists "reviewer update claims" on public.entity_ownership_claims;
create policy "reviewer update claims" on public.entity_ownership_claims
for update to authenticated using (
  (select private.is_superadmin())
  or (select private.can_manage_organization(organization_id))
) with check (
  status in ('pending', 'approved', 'rejected')
);

-- ------------------------------------------------------------
-- 2.1.3 Funció RPC: Aprovar reclamació i assignar rol owner
-- ------------------------------------------------------------
create or replace function public.approve_ownership_claim(p_claim_id uuid)
returns void
language plpgsql security definer set search_path = ''
as $$
declare
  v_org_id uuid;
  v_tenant_id uuid;
  v_claimant uuid;
begin
  if not (select private.is_superadmin()) then
    raise exception 'Només un superadministrador pot aprovar reclamacions.' using errcode = '42501';
  end if;

  select organization_id, tenant_id, claimant_user_id
  into v_org_id, v_tenant_id, v_claimant
  from public.entity_ownership_claims
  where id = p_claim_id and status = 'pending';

  if not found then
    raise exception 'Reclamació no trobada o ja processada.' using errcode = '22023';
  end if;

  -- Assignar com a admin (no owner per defecte; superadmin decideix després si promou)
  insert into public.organization_memberships (organization_id, tenant_id, user_id, role)
  values (v_org_id, v_tenant_id, v_claimant, 'admin')
  on conflict (organization_id, user_id) do update set role = 'admin';

  update public.entity_ownership_claims
  set status = 'approved', reviewed_by = (select auth.uid()), reviewed_at = now()
  where id = p_claim_id;
end;
$$;
revoke execute on function public.approve_ownership_claim(uuid) from public, anon;
grant execute on function public.approve_ownership_claim(uuid) to authenticated;

-- ------------------------------------------------------------
-- 2.1.4 Millora RLS: Organització pot llegir membres si és member
-- ------------------------------------------------------------
drop policy if exists "members read own memberships" on public.organization_memberships;
create policy "members read own memberships" on public.organization_memberships
for select to authenticated using (
  user_id = (select auth.uid())
  or (select private.can_manage_organization(organization_id))
  or (select private.is_superadmin())
);

-- ------------------------------------------------------------
-- 2.1.5 Vista: identitats disponibles per a l'usuari actual
-- (persona + organitzacions on és member)
-- ------------------------------------------------------------
create or replace view public.my_identities
with (security_barrier = true)
as
-- La meva identitat personal
select
  p.id as id,
  'persona' as type,
  null as slug,
  p.full_name as nom,
  'Tu' as rol,
  null as kind,
  null as parent_organization_id
from public.profiles p
where p.id = (select auth.uid())

union all

-- Les meves organitzacions
select
  o.id as id,
  'entitat' as type,
  o.slug as slug,
  o.name as nom,
  m.role as rol,
  o.kind as kind,
  o.parent_organization_id
from public.organization_memberships m
join public.organizations o on o.id = m.organization_id and o.tenant_id = m.tenant_id
where m.user_id = (select auth.uid());

revoke all on table public.my_identities from public, anon;
grant select on table public.my_identities to authenticated;
```

### 3.2 Assignació de Rols

| Rol | Abast | Com s'assigna |
|---|---|---|
| **Superadministrador** | Plataforma sencera | Manualment per un altre superadmin via `platform_roles` |
| **Owner** | Una organització | Automàtic en crear-la (trigger `add_organization_owner`). Només un per organització (índex únic). |
| **Admin** | Una organització | Per un owner existant o via aprovació de reclamació |
| **Member** | Una organització | Per owner/admin. Lectura + escriptura bàsica. |
| **Town Member** | Un poble/tenant | Automàtic en crear la primera organització al poble |

### 3.3 Reclamació de Propietat d'Entitats Existents

**Cas d'ús**: Una persona real és el representant legítim d'una empresa/ajuntament/associació que ja existeix a la base de dades (sembrada o creada per un altre), però no té accés.

**Flux**:
1. L'usuari autenticat va a la fitxa de l'entitat pública
2. Clica "Reclamar la propietat d'aquesta entitat"
3. Omple un camp `evidence` (10-2000 caràcters) explicant el motiu i acreditant la relació
4. Es crea un registre a `entity_ownership_claims` amb `status = 'pending'`
5. Un **superadministrador** rep la notificació
6. Superadministrador verifica i aprova/rebutja
7. Si s'aprova: funció `approve_ownership_claim()` afegeix l'usuari com a `admin` a `organization_memberships`
8. L'admin ja pot gestionar l'entitat; si cal, un owner existent pot promoure'l a owner

## 4. Canvis en el Front-end

### 4.1 Refinament de `IdentitatContext.jsx`

L'actual ja és correcte. Cal ampliar per carregar les `memberships` reals des de backend:

```jsx
// src/app/contexts/IdentitatContext.jsx — MODIFICACIÓ PROPOSADA
import { createContext, useContext, useEffect, useState, useMemo, useCallback } from 'react';
import { useLocation, matchPath } from 'react-router-dom';
import { useSession } from './SessionContext';
import { getDefaultUserId, listMyOrganizations } from '../../data/backendPort';

const IdentitatContext = createContext(null);

export function IdentitatProvider({ children, externalConfig }) {
  const { currentUser } = useSession();
  const location = useLocation();

  let actorType = 'persona';
  let actorId = currentUser?.id || getDefaultUserId();

  const entitatMatch = matchPath('/e/:slug/*', location.pathname);
  if (entitatMatch) {
    actorType = 'entitat';
    actorId = entitatMatch.params.slug;
  } else if (location.pathname.startsWith('/jo')) {
    actorType = 'persona';
  }

  const actorKey = `${actorType}::${actorId}`;
  const [organizations, setOrganizations] = useState([]);
  const [loadingOrgs, setLoadingOrgs] = useState(false);

  const loadOrgs = useCallback(async () => {
    if (!currentUser?.id) {
      setOrganizations([]);
      return;
    }
    setLoadingOrgs(true);
    try {
      const rows = await listMyOrganizations(externalConfig);
      setOrganizations(rows);
    } catch (e) {
      console.error('[IdentitatContext] Error carregant organitzacions', e);
    } finally {
      setLoadingOrgs(false);
    }
  }, [currentUser?.id, externalConfig]);

  useEffect(() => { loadOrgs(); }, [loadOrgs]);

  // memberships: llista completa { id, type, slug, nom, rol, kind }
  const memberships = useMemo(() => {
    const persona = currentUser ? [{
      id: currentUser.id,
      type: 'persona',
      slug: null,
      nom: currentUser.user_metadata?.name || 'Tu',
      rol: 'Tu',
      kind: null
    }] : [];
    const orgs = organizations.map(o => ({
      id: o.id,
      type: 'entitat',
      slug: o.slug,
      nom: o.name,
      rol: o.role,
      kind: o.kind
    }));
    return [...persona, ...orgs];
  }, [currentUser, organizations]);

  const value = useMemo(() => ({
    actorType,
    actorId,
    actorKey,
    memberships,
    organizations,
    loadingOrgs,
    refreshOrganizations: loadOrgs
  }), [actorType, actorId, actorKey, memberships, organizations, loadingOrgs, loadOrgs]);

  return (
    <IdentitatContext.Provider value={value}>
      {children}
    </IdentitatContext.Provider>
  );
}

export function useIdentitat() {
  const context = useContext(IdentitatContext);
  if (!context) throw new Error('useIdentitat ha de ser usat dins de IdentitatProvider');
  return context;
}
```

## 5. Implementació del Backend Supabase

### 5.1 Mètodes que cal implementar a `supabaseBackend.js`

Llista de mètodes de `backendPort.js` i la seua correspondència Supabase:

| Mètode backendPort | Implementació Supabase |
|---|---|
| `registerWithEmail(email, password, name)` | `supabase.auth.signUp({ email, password, options: { data: { name } } })` |
| `loginWithEmail(email, password)` | `supabase.auth.signInWithPassword({ email, password })` |
| `loginWithGoogle()` | `supabase.auth.signInWithOAuth({ provider: 'google' })` |
| `logout()` | `supabase.auth.signOut()` + netejar localStorage |
| `getCurrentUser()` | `supabase.auth.currentUser` o llegir de localStorage |
| `listMyOrganizations()` | `supabase.rpc('list_my_organizations', { p_tenant_id })` |
| `createOrganization(blueprint)` | `supabase.rpc('create_organization', { ...params })` |
| `getProfile()` | `supabase.from('profiles').select('*').eq('id', uid).single()` |
| `updateProfile(changes)` | `supabase.from('profiles').update(changes).eq('id', uid)` |

### 5.2 Persistència de Sessió

Supabase gestiona automàticament la sessió via `localStorage` (clau `sb-<ref>-auth-token`). A més, el projecte manté les seues pròpies claus:
- `socdepoble-user`: Objecte usuari
- `socdepoble-jwt`: Token JWT

**Recomanació**: Unificar i utilitzar només la sessió nativa de Supabase. Subscriure's a `supabase.auth.onAuthStateChange()` per disparar `sdp:auth-change`.

## 6. Seguretat i RLS (Row Level Security)

### 6.1 Princips Respectats
- ✅ **Perfil sempre privat**: `profiles.visibility = 'private'` (check constraint + RLS)
- ✅ **Online-First**: Tot passa per Supabase; no hi ha sincronització local complexa
- ✅ **SDP-LOCK**: Trigger `sdp_protegeix_propietari` impedeix deixar una organització sense owner
- ✅ **Un sol owner per organització**: Índex únic `idx_organization_memberships_one_owner`
- ✅ **Superadmin separat**: Taula `platform_roles` amb accés restringit
- ✅ **Consentiment RGPD**: Camp `consentiment_rgpd_at` a `profiles` amb default `now()`

### 6.2 Verificació de Polítiques RLS Crítiques

| Taula | Política | Estat |
|---|---|---|
| `profiles` | Només el propi usuari pot llegir/escriure | ✅ Existent |
| `organizations` | Públiques llegibles per tothom autenticat; membres veuen les seues | ✅ Existent |
| `organization_memberships` | Només un mateix o admin/owner/superadmin pot llegir | ✅ Millorat en §2.1.4 |
| `platform_roles` | Només superadmin pot accedir | ✅ Nou |
| `entity_ownership_claims` | Claimant veu la seua; admin/owner/superadmin veuen les de la seua org | ✅ Nou |
