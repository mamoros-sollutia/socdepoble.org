- **Cap CI al manifest** (cap `.github/`). Tot el cicle de qualitat viu en hooks locals → saltable amb `--no-verify`. La llei és local; el repositori, anarquia potencial. A 5 anys i 3 col·laboradors, un dissabte per pressa crea deriva invisible fins al següent bundle.

### 2.3 🟠 Contingut com a codi (contradicció estructural)

- `pageContent.js` (107 KB), `legalContent.js` (22 KB), `DesignSectionContent.jsx` (59 KB) i **`Aplec2023Article.jsx` — un article del 2023 com a component React** — en un projecte **Online-First amb Supabase darrere**. La base de dades ja existeix per a açò; el bundle es queda amb la biblioteca en lloc del motor.
- **Triplicitat de llavors**: seeds JS ↔ `seed.sql` generat ↔ contingut hardcodat. La generació unidireccional existeix (bé), però res creua la coherència.
- Tokens en **tres llocs** (`design-tokens.json`, `design-tokens.css`, `theme.js`) — fonts de veritat múltiples.

### 2.4 🟠 Seguretat sense proves

- Els tres punts més sensibles — `sanitize.js`, `oauthRelay.js`, `callback.html` (HTML amb JS inline manipulant tokens) — són els tres **sense un sol test**.
- `tractor-rls` és estàtic: llegeix polítiques, no les executa. Cap CSP evidenciada al manifest. Els hash del bundle verifiquen bytes, no comportament.
- **El contracte d'abast no declara lockfile.** Si no n'hi ha, les construccions no són reproduïbles — contradicció frontal amb la cultura SHA-256 (pot ser a la cua truncada; verifiqueu-ho avui).

### 2.5 🟠 Estat difús

- **10 React contexts**; Notes en té **dos** (`NotesContext` 10 KB + `NotesDataContext` 3 KB). Propietat de l'estat difusa → risc de tempestes de re-render en mòbils vells. El vostre públic és gent gran amb terminals humils: el coll d'ampolla és el primer carregament.

- Esquelets buits (`feedSeed.js` = 29 B), `schema_notes.sql` (notes en .sql), `nl_final:false` en fitxers que el vostre propi sistema detecta i no corregeix, `poblacio/` vs `pobles/` (fricció cognitiva futura).

- ≈190 fitxers de meta-eina amb **un sol fitxer de test propi** (`test_brain_tools.py`, 8 KB, per ~65 eines). El sistema immunitari no té sistema immunitari. Part del que diagnostic **ja el sabeu**: els vostres registres de deute són el confessor; falta el penediment (execució).

## 3. Trajectòries de fallida a 5 anys

1. **La veritat local**: les portes es salten un dia; la deriva és invisible fins que el següent bundle la congela com a «veritat» amb hash.
2. **Creixement lineal del payload**: cada secció nova afegeix JS+CSS+i18n al chunk inicial.
3. **Sediment**: naixerà `append_css7.mjs`; el patró de mutació no s'atura sol.
4. **Por a migrar**: 934 línies d'schema + RLS sense tests SQL → cada canvi de schema serà traumàtic; el contracte Sollutia evolucionarà i no hi ha tests de contracte.
5. **Bus factor 1 + inversió meta**: si el mantenidor para, el tractor deixa de rebre combustible i 190 fitxers de meta queden orfe.
6. **Concurrència**: 83 KB d'i18n + 129 KB de CSS = hotspots de conflicte per a un Consell multi-escriptor.
7. **Drift semàntic**: wiki ↔ seeds ↔ schema sense creuament de coherència.

## 4. Redisseny resilient

**Principis:** cap proposta trenca l'ADR-2026-08 (Online-First); cap patró Local/Offline-First que enfosquisca la realitat; **cap dependència nova en runtime** (màxim un devDep opcional); el CSS es manté artesà, sense Tailwind.

### Fase 0 — Llei i higiene (0–3 mesos, cost baix)

1. **Pugeu el torn al CI** (GitHub Actions o runner propi tipus Gitea+Woodpecker si la sobirania mana): `verify.mjs`, portes, build, tests i **recomputació del manifest en màquina**. Els hash, calculats per algú que no siga qui ha creat el bundle.
2. **Porta nova `tractor-limits.mjs`**: ≤300 línies/fitxer, ≤120 columnes, ≤20 KB; cada excèp genera entrada automàtica al vostre sistema de deute — el registre ja existeix, useu-lo com a pressió.
3. **Arxiveu els 12+ scripts d'un sol ús a `90_arxiu_historic`** (el directori ja és al contracte d'abast) i regla nova: `scripts/` només eines idempotents amb capçalera d'ús.
4. Formatador via ESLint (ja teniu `eslint.config.js`) per a matar les línies de 839/4.674 B; el generador de seed ha d'emetre INSERT multilínia.
5. **Tests de la tríada de seguretat**: `sanitize` (vectors XSS), `oauthRelay` (estat/CSRF), `callback` (neteja de hash). ~25 tests, el màxim llevant per hora invertida.
6. `CHANGELOG.md`, `SECURITY.md` i runbook de còpies+restauració de Supabase (prova trimestral), lligat al Protocol Lázaro.
7. Convenció única de migracions + lockfile declarat al contracte d'abast.

### Fase 1 — Estructura (3–12 mesos)

1. **Tallar `supabaseBackend.js` per domini** (auth/contingut/xat/storage) darrere de `backendPort.js`; el port com a única superfície d'importació de les seccions. ADR nou per al canvi.
2. **Carrega per secció** (`React.lazy` + chunks de Vite, zero dependències): chunk inicial −40/60%; i18n per locale amb import dinàmic.
3. **Contingut a la base de dades**: pageContent/legal → taules Supabase amb el pipeline wiki→seed→DB que ja teniu. El bundle es queda amb el motor.
4. **CSS**: tokens generats des del JSON únic (porta que detecte el drift), `index.css` dividit per secció (el patró `NotesSection.css` ja és el model), límit de pes per porta.
5. **Dieta de contexts**: fusionar els dos de Notes; mapa de propietat d'estat documentat.
6. JSDoc + `--checkJs` a les fronteres (port, seeds, `UniversalUtils`): tipus a les costures, zero cost de runtime.
7. **Tests SQL de RLS en CI** (asserts senzills via `supabase db reset`): `tractor-rls` passa d'estàtic a viu.

### Fase 2 — Sobirania escalable (1–5 anys)

1. **Contracte Sollutia versionat** (JSON Schema/OpenAPI) + tests de contracte com a porta + política de finestres de deprecació. El `.sollutia-deute.json` (272 B) és quasi buit: o el deute és mínim o està subregistrar — registreu-lo.
2. **Cicle de vida del tooling**: frontmatter amb propietari i invocació per a cada porta; purga anual com a data fixa (el script `purga_maquinari` ja existeix — instituïu-la).
3. **Observabilitat pròpia i lawful**: taula d'esdeveniments/salut a Supabase + reporter mínim, alineat amb LLEI_05; cap SaaS de tercers.
4. **Governança multi-escriptor**: protecció de branques + torn signat (LEDGER referenciat al PR). L'escala d'1 a N mantenidors.
5. Articles com a registre editorial, no com a JSX: `mur/articles` no pot ser abocador de components.
6. Via d'evolució documentada: el port/adapter garanteix que qualsevol migració futura de backend siga **un ADR nou, no una reescriptura**.

## 5. El regal als futurs programadors i màquines

- **Una porta**: `npm run torn | portes | test | bundle | verificar` com a única interfície per a humans i IA.
- **Un mapa**: un `INICI_ACÍ.md` que encadene BIOS → ARCHITECTURE → portes → tests.
- **La llei en màquines, no en memòria**: CI + límits + deute registrat.
- **Els hash sempre recomputables per un tercer.**

Esteu a un 70% d'aquest regal: us falten l'execució distribuïda (CI) i els límits de mida.
