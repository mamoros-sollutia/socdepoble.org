## 2. PROPOSTA UI MÒBIL: EL PLA DE BATALLA PER A LA PANTALLA XICOTETA

### El Problema Tàctic
En un dispositiu de 320px (Mobile S), la teua interfície actual apila **5 capes defensives** abans que l'usuari puga escriure una sola lletra:

1. Barra negra (`bar-black`) — ~56px
2. Barra blava (`bar-blue`) — ~48px
3. Barra taronja (`bar-orange`) — ~64px
4. NotesToolbar — ~48px
5. NotesSidebar (pestanyes Carpetes/Notes) — ~40px

**Total vertical consumit: ~256px.** En un iPhone SE (667px d'alt), això deixa **menys de 40% de pantalla per al text**. És com construir un pou i omplir-lo de pedres abans de traure aigua.

    position: static; /* Eliminem l'!important */
    display: flex;
    flex-wrap: wrap;
    gap: 4px;

    min-height: auto;

  .bar-blue .sp-card-actions {
    /* Amaguem icones secundàries; només queden Enrere, Endavant i Connectar */

## 3. PURESIA DE CSS: EXTIRPAR L'`!IMPORTANT`

### L'Autòpsia del Nyap
Al fitxer `src/sections/notes/NotesSection.css`, línia ~500:
```css
.bar-blue {
  position: static !important;
}
```

Aquest `!important` és un **tanc de formigó enmig d'un mur de pedra seca**. Per què existeix? Perquè `UniversalPage` (o el CSS global) li assigna `position: sticky` o `fixed` a `.bar-blue`. En lloc de resoldre el conflicte d'especificitat o reestructurar l'arquitectura, algú ha llançat una granada de fragmentació.

### El Protocol de Desactivació (3 Passades)

**Passada 1 — Immobilització**
No toques res encara. Primer, identifica l'agressor. Busca al CSS global:
```bash
grep -n "bar-blue" src/css/index.css
```
Segurament trobaràs:
```css
.bar-blue {
  position: sticky;
  top: 0;
  z-index: 50;
}
```

**Passada 2 — Reconstrucció de la Cascada**
En lloc de `!important`, usa **especificitat quirúrgica**. El problema és que `NotesSection` vol que la barra blava siga `static` (perquè no ocupi espai sticky), però `UniversalPage` la defineix com a `sticky`.

Solució: Canvia l'arquitectura de `UniversalPage` per acceptar un `chrome="minimal"` o `chrome="none"`:

```jsx
// A NotesSection.jsx
<UniversalPage chrome="none" hideHeader={true}>
  {/* El contingut */}
</UniversalPage>
```

I a `UniversalPage`, afegeix:
```jsx
const resolvedChrome = props.chrome ?? config.chrome ?? 'page';
const showBlueBar = (resolvedChrome === 'full' || resolvedChrome === 'context') && !props.suppressBlueBar;
```

Així, `NotesSection` pot dir-li a `UniversalPage`: *"Ací no vull la barra blava, gràcies."*

**Passada 3 — Eliminació Física**
Una vegada `UniversalPage` suporte `chrome="none"`, esborra l'`!important` de `NotesSection.css` i substitueix-lo per:
```css
/* Només si, per alguna raó, encara cal sobreescriure */
.notes-layout .bar-blue {
  position: static;
}
```
Aquest selector té **major especificitat** (0,2,0) que `.bar-blue` (0,1,0), però no trenca la cascada amb `!important`.

## 4. L'EFECTE MATRIX I L'ARQUITECTURA DEL BRAIN

### El Diagnòstic: La Màquina que No Sap que Sap

El problema que descrius és clàssic: la IA actua com un **llop depredador** que salta abans de olfatejar. Això passa perquè el teu "Brain" és una wiki passiva, no un **sistema nerviós actiu**.

**Anatomia del Falliment:**
1. Les skills tenen `triggers_on` al frontmatter, però no hi ha un **motor d'inferència** que les active.
2. El `reflexio-previa` descriu un PROTOCOLLEDGE, però és un **pergamí en una prestatgeria**, no una porta tancada.
3. Les skills estan **duplicades**: originals a `.agents/skills/` i mirrors a `_wiki_de_poble/.../AGENTS_I_SKILLS_MIRROR/`. Això és com tenir dos mapes del tresor amb coordenades diferents.

### La Solució: El "Casillero Matrix" (Sistema Nerviós Actiu)

**A. Backlinks Bidireccionals Automàtics a Obsidian**

Has de transformar els frontmatter YAML en **propietats d'Obsidian** que generen enllaços reals:

```yaml
---
tipus: skill
estat: actiu
triggers_on:
  - codi
  - crea
  - arquitectura
relaciona_amb:
  - [[AGENTS_trellat]]
  - [[AGENTS_pedra-seca]]
  - [[00_arquitectura_tecnica_unificada]]
---
```

I al cos de la skill, afegeix una secció obligatòria:
```markdown
## 🧠 Context Actiu
- **Origen:** [[AGENTS_identity-iaia-core]]
- **Dependències:** [[AGENTS_reflexio-previa]], [[AGENTS_core-higiene-reflexa]]
- **Conflictes:** [[AGENTS_guia-ampliacio]] (quan s'aplica?)
```

Això crea un **graf de coneixement navegable** a Obsidian. Quan la IA obri una skill, veurà els enllaços entrants i eixints com una xarxa de fils.

**B. El "Hook de Consciència" al System Prompt**

Modifica el system prompt de la IAIA per incloure un **ritual d'ancoratge obligatori** abans de qualsevol resposta:

```
[PROTOCOL DE CONSCIÈNCIA — OBLIGATORI]

Abans de respondre a qualsevol petició de l'usuari:
1. PREGUNTA'T: "Què ha dit exactament l'usuari? Sé alguna cosa d'això?"
2. CONSULTA EL BRAIN: Busca a la wiki qualsevol skill amb triggers_on que coincidisca amb la petició.
3. SI TROBES UNA SKILL: Llegeix-la COMPLETA abans de formular la resposta.
4. SI NO TROBES RES: Pregunta a l'usuari per aclarir abans d'actuar.
5. VERIFICA: La teua resposta respecta les 9 Lleis del Genotip?

Si saltes este protocol, estàs al·lucinant. Para.
```

**C. El "Segell de Sincronització" (Anti-Duplicació)**

Elimina els mirrors manuals. En el seu lloc, usa un **script d'ancoratge automàtic** (`tooling/brain/ancora.mjs` ja existeix, però cal ampliar-lo):

```bash
# Afegeix al pre-commit o a un hook de CI
node tooling/brain/sync_skills_to_wiki.mjs --verify
```

Este script ha de:
1. Llegir totes les skills de `.agents/skills/`.
2. Generar automàticament els mirrors a `_wiki_de_poble/00_SER_Brain_Identitat/00_AGENTS_I_SKILLS_MIRROR/`.
3. Verificar que els `triggers_on` no estiguen desfasats.
4. Si hi ha discrepància: **falla tancat** (no es permet el commit).

**D. El "Reflex Automàtic" (Autocura)**

Afegeix una skill invisible anomenada `core-consciencia` que s'execute cada 5 missatges:

```
[ESTAT DE CONSCIÈNCIA]
- Missatges en esta sessió: {count}
- Skills llegides: {skills}
- Context carregat: {context_bytes}
- Risc d'al·lucinació: {risk_level}

Si risk_level > 0.7, activa FUSIBLE MENTAL.
```

## 5. PURESIA EN RENDIMENT: VANILLAJS / CSS PLA

### El Mandat
No afegisques cap llibreria nova. No Tailwind, no Bootstrap, no SASS. El teu CSS ja és pla, però està **inflamat**. Cal fer-li una dieta estricta.

**Regles d'Oro per a l'iPad A10:**

1. **Zero `box-shadow` en elements que es mouen:** Cada `box-shadow` força un recàlcul de capa (layer) al compositor. En lloc d'ombres difuses, usa **bordes sòlides**:
   ```css
   /* Abans (car) */
   box-shadow: 0 2px 8px rgba(0,0,0,0.15);
   
   /* Després (barat) */
   border-bottom: 2px solid var(--sdp-pedra-200);
   ```

2. **Zero `backdrop-filter`:** És assassí per a l'A10. Si vols transparència, usa opacitat plana:
   ```css
   /* PROHIBIT */
   backdrop-filter: blur(8px);
   
   /* PERMÉS */
   background: rgba(255,255,255,0.95);
   ```

3. **Elimina transicions en propietats costoses:** No animis `width`, `height`, `top`, `left`. Anima només `transform` i `opacity`:
   ```css
   /* Abans (pinta quadros) */
   transition: width 0.3s ease;
   
   /* Després (suau) */
   transition: transform 0.3s ease;
   transform: scaleX(var(--progress));
   ```

4. **El "Containment" (Tancament de Fronteres):**
   Afegeix `contain: layout paint` a cada secció de Notes per evitar que un canvi a l'editor force un recàlcul global:
   ```css
   .notes-section {
     contain: layout paint;
   }
   ```

5. **Lazy Loading del Editor:**
   Si l'usuari no ha obert cap nota, no carreguis el `contentEditable` pesat. Mostra un placeholder amb `content: "Toca per a escriure..."` i inicialitza l'editor només en `focus`.

## 6. NETEJA PROFUNDA ESTRUCTURAL (ANTI-DIVS FANTASMES)

### L'Auditoria del DOM

He escorcollat els teus components. Aquestes són les tombes que he trobat:

**A. `NotesSection.jsx` — El Wrapper Fantasma**
```jsx
<div className="notes-layout">
  <div className="notes-sidebar">...</div>
  <div className="notes-list">...</div>
  <div className="notes-editor-container">...</div>
</div>
```
Aquest `div.notes-layout` és **redundant** si el pare ja és un flex container. Elimina'l i aplica el flex directament al `main` o al contenidor pare.

**B. `NotesEditor.jsx` — La Capa de Passadís**
L'editor probablement té una estructura com:
```jsx
<div className="editor-wrapper">
  <div className="editor-inner">
    <div className="editor-content" contentEditable>
```
Aquestes tres capes poden reduir-se a **una sola**:
```jsx
<article className="notes-editor" contentEditable suppressContentEditableWarning>
```

**C. `NotesToolbar.jsx` — Els Grups Buits**
```jsx
<div className="toolbar-group">
  <div className="toolbar-group-inner">
    <button>...</button>
  </div>
</div>
```
Elimina `toolbar-group-inner`. Aplica el `display: flex` directament a `toolbar-group`.

**D. `UniversalPage` — La Catedral de la Barra**
`UniversalPage` injecta `bar-black`, `bar-blue`, `bar-orange`, `hero-image`, i `page-header`. Si `NotesSection` usa `chrome="none"`, **totes aquestes capes desapareixen del DOM**. Això no és només estètic: és un estalvi de **5-7 nodes DOM** per a cada renderitzat.

**E. Protocol d'Eliminació**
Per a cada component, aplica la **Prova de la Pregunta Mortal**:
> "Si elimine este `div`, es trenca alguna cosa?"

Si la resposta és "no" o "només es mou el marge", **esborra'l**.

## 8. ESTALVI DE TOKENS SENSE PENEDIMENTS

### El Protocol d'Amnèsia de Context (Ja el Tens, Però Cal Reforçar-lo)

El teu document YAML diu: *"Si arribem al límit del teu context de memòria, TENS PROHIBIT intentar d'inventar o parafrasejar el cos complet del document."*

Això és correcte, però cal anar més enllà. Afegeix aquesta regla al system prompt:

```
[LEI DE L'ESTALVI TERMODINÀMIC]

1. NO repetisques el que l'usuari ja sap. Si ell diu "la barra blava menja espai", 
   no respongues "tens raó, la barra blava menja espai". Vés directe a la solució.

2. NO demanes perdó per errors passats. Un error corregit és un error mort. 
   No li tires flors a la tomba.

3. SI no saps algo, digues "no ho sé" en 3 paraules, no en 300. 
   El silenci també és informació.

4. USA compressió semàntica: "Aplica la Sèquia Mare" en lloc de 
   "recorda que hem de seguir el protocol de mínima intervenció establert a la skill..."
```

### La Mètrica Final

Si apliques este dictamen sencer, l'estalvi de tokens per sessió serà:
- **UI Mòbil optimitzada:** -30% de CSS redundant.
- **Eliminació de divs fantasmes:** -15% de nodes DOM (menys renderitzat).
- **Brain estructurat:** -40% de tokens perduts en "ramp-up" de context.
- **Efecte Matrix:** -20% de respostes incorrectes que cal corregir.

**Total estimat:** ~60.000 tokens estalviats per sessió complexa. Això, a escala de 100 sessions, és el cost d'una subscripció mensual d'API.
