### 1. Proposta UI Mòbil (< 768 px) — maximitzar viewport útil

Objectiu: deixar només la zona d’escriptura visible per defecte i fer aparèixer la resta sota demanda, sense trencar l’estètica Pedra Seca.

**Arquitectura de pantalles**

- **Vista per defecte (escriptura)**: només Editor + Toolbar compacta.
- **Vista llista**: full-screen overlay o panel deslizant des de l’esquerra.
- **Vista carpetes**: mateix panel, amb pestanyes internes o swipe.

**Implementació concreta (Vanilla CSS + mínim JS)**

```css
/* Dins NotesSection.css — afegir al final */

@media (max-width: 767px) {
  .notes-shell {
    flex-direction: column;
    height: 100dvh;                    /* millor que 100vh a iOS */
    min-height: 100dvh;
    position: relative;                /* ja no cal sticky propi */
  }

  /* Les dues columnes laterals es converteixen en overlay */
  .notes-column--left,
  .notes-column--middle {
    position: fixed;
    inset: 0;
    width: min(100%, 320px);
    z-index: 40;
    transform: translateX(-100%);
    transition: transform 0.22s cubic-bezier(0.2, 0.7, 0.3, 1);
    box-shadow: var(--sdp-ombra-3);
  }

  .notes-column--left.is-open,
  .notes-column--middle.is-open {
    transform: translateX(0);
  }

  /* Overlay de fons quan un panell està obert */
  .notes-shell::after {
    content: "";
    position: fixed;
    inset: 0;
    background: rgba(0,0,0,0.35);
    opacity: 0;
    pointer-events: none;
    transition: opacity 0.2s;
    z-index: 30;
  }
  .notes-shell.has-panel-open::after {
    opacity: 1;
    pointer-events: auto;
  }

  /* Toolbar: es redueix i es fa sticky només dins de l’editor */
  .editor-toolbar {
    position: sticky;
    top: 0;
    z-index: 10;
    height: 48px;
    min-height: 48px;
    padding: 0 8px;
    gap: 4px;
    overflow-x: auto;
    scrollbar-width: none;
  }
  .editor-toolbar::-webkit-scrollbar { display: none; }

  /* Amagar text “PUBLICAR” i deixar només icona en mòbil */
  .btn-publish span { display: none; }
  .btn-publish { padding: 0 12px; }

  /* Capçalera de columnes: més baixa */
  .notes-column-header {
    height: 48px;
    min-height: 48px;
  }
}
```

**JS mínim (dins NotesSection o NotesContext)**

```js
// Control d’obertura dels panells
function openPanel(which) {
  document.querySelector('.notes-shell')?.classList.add('has-panel-open');
  document.querySelector(`.notes-column--${which}`)?.classList.add('is-open');
}
function closePanels() {
  document.querySelector('.notes-shell')?.classList.remove('has-panel-open');
  document.querySelectorAll('.notes-column--left, .notes-column--middle')
    .forEach(el => el.classList.remove('is-open'));
}
```

**Botons de navegació mòbil** (dins de l’editor o de la toolbar):

- Icona “Carpetes” → `openPanel('left')`
- Icona “Notes” → `openPanel('middle')`
- Tocar el fosc o botó “Tancar” → `closePanels()`

Això recupera ~110-140 px verticals immediatament i deixa l’editor com a protagonista.

### 2. Puresa de CSS: eliminar l’`!important` de la barra blava

El problema actual:

```css
:host(:has(.notes-shell)) header.bar-blue,
.sdp-root:has(.notes-shell) header.bar-blue,
... {
  position: static !important;
}
```

**Solució neta (especificitat + cascade layer o selector més específic)**

1. Assegura’t que la regla de la barra blava original no porta `!important`.
2. Puja l’especificitat de la regla de Notes sense `!important`:

```css
/* En lloc de !important */
.sdp-root:has(.notes-shell) header.bar-blue,
.app-main:has(.notes-shell) > header.bar-blue,
:host(:has(.notes-shell)) header.bar-blue {
  position: static;
  /* o position: relative; si vols mantenir el flux */
}
```

Si la regla original de `header.bar-blue` és molt específica (per exemple `.sdp-root header.bar-blue.sticky`), replica exactament la mateixa cadena i afegeix `:has(.notes-shell)`.

Alternativa més robusta (recomanada):

```css
/* Al fitxer global de layout, no a NotesSection.css */
@layer layout {
  header.bar-blue {
    position: sticky;
    top: 0;
  }
}

@layer notes {
  .sdp-root:has(.notes-shell) header.bar-blue {
    position: static;
  }
}
```

Les cascade layers resolen el conflicte sense `!important` i sense guerres d’especificitat.

### 3. Efecte Matrix + Arquitectura del Brain (Obsidian + system prompts)

**A. Propietats i etiquetes de les skills (xarxa bidireccional)**

Cada skill ha de portar un frontmatter mínim i tancat:

```yaml
---
name: pedra-seca
description: ...
version: 1.2.0
status: activa
lang: ca-valencia
triggers_on:
  - ui
  - disseny
  - notes
  - css
depends_on:
  - identity-iaia-core
  - trellat
related:
  - design_system_specs
  - universal_maquetation
tags:
  - skill
  - ui
  - mobile
  - notes
---
```

Regles:

- `triggers_on` és l’única clau de disparador canònica (ja la teniu als tractors).
- `depends_on` + `related` generen enllaços bidireccionals automàtics via el teixidor (`teixidor-backlinks.mjs` o equivalent).
- Vocabulari de `tags` tancat (ja teniu `.vocabulari-deute.json`). Cap tag nou sense passar pel tractor.

Això permet a la IA fer una cerca semàntica o per tags i recuperar ràpidament el context rellevant sense “inventar”.

**B. System prompt / hàbit reflexiu (irrompible)**

Afegiu al prompt de sistema (o a la skill `core-context-panic` / `reflexio-previa`) un protocol obligatori abans de qualsevol resposta tècnica:

```
PROTOCOL MATRIX (obligatori abans de respondre):
1. Llegeix la pregunta i identifica els conceptes clau.
2. Consulta primer el brain (skills + wiki) amb els tags/triggers corresponents.
3. Si no trobes res, digues-ho explícitament: “No tinc aquesta skill al brain”.
4. Només després de 1-3 genera la resposta.
5. Si la resposta implica CSS/UI, obri obligatòriament design_system_specs.md i universal_maquetation.md.
```

Feu que aquest protocol siga el primer bloc del system prompt i que el tractor de doctrina el verifique (ja teniu `validate-wiki-compliance.mjs` i els tractors de frontmatter).

### 4. Puresa de rendiment (VanillaJS / CSS pla)

- Zero libreries noves per al mode mòbil.
- Transicions només amb `transform` i `opacity` (GPU).
- `100dvh` en lloc de `100vh`.
- Toolbar amb `overflow-x: auto` i `scrollbar-width: none`.
- Cap `position: sticky` global quan estem en mode Notes; el sticky es queda dins de l’editor.
- El panell d’overlay es destrueix del flux (fixed) → zero impacte en el layout de l’editor.
