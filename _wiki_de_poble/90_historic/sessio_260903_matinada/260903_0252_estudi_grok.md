## 1. Diagnòstic del trencament de maquetació

### 1.1 Origen principal (CSS / DOM)

El shell de tres columnes depèn de cadena d’alçada i de `:has()`:

```css
.content-wrapper:has(.notes-shell) {
  flex: 1 1 auto;
  min-height: calc(100vh - var(--sdp-alt-negra));
  padding: 0;
  overflow: visible;
}

.notes-shell {
  height: calc(100vh - var(--sdp-alt-negra));
  min-height: calc(100vh - var(--sdp-alt-negra));
  overflow: hidden;
  position: sticky;
  top: var(--sdp-alt-negra);
}
```

**Problemes concrets:**

| Causa | Efecte |
|--------|--------|
| `UniversalPage` amb `chrome="none"` + `variant="embed"` | El contenidor pare pot **no** exposar `--sdp-alt-negra` ni l’estructura `.content-wrapper` esperada → alçada col·lapsa o sobreeix. |
| `position: sticky` + `height: 100vh − barra` | En host WordPress / shadow / barres d’admin, el viewport útil canvia → columna editor “tallada” o scroll intern mort. |
| Mòbil: columnes `position: absolute` + `opacity: 0` / `pointer-events: none` | Si `mobilePanel` no es sincronitza amb la selecció de nota, es veu panell buit o “desmuntat”. |
| `data-editant={mobilePanel === 'editor'}` + CSS que **amaga** la toolbar quan `data-editant="true"` | A mòbil, en entrar a l’editor la barra de format **desapareix** exactament quan cal. Això es percep com a “s’ha desmuntat”. |
| `EditorContent` amb `style` inline (`min-height: 300px; flex: 1`) | Competeix amb el flex del CSS de columna; en alçades curtes el cos es comprimeix o desborda. |

### 1.2 Cadena de panels mòbil

`NotesContext` inicialitza `mobilePanel: 'folders'`.  
`handleSelectNote` (parcialment truncat al bundle) ha de forçar `setMobilePanel('editor')`. Si no ho fa de forma fiable, l’usuari es queda amb la columna de carpetes/llista invisible i l’editor ocult → sensació de layout trencat.

### 1.3 Conclusió layout

No és un “bug de TipTap” ni de Lucide. És **topologia de flex + sticky + panel mòbil mal acoblat** i una regla mòbil que amaga la toolbar en mode editor.

## 2. Icones de la barra de format

### 2.1 Estat actual (`NotesToolbar.jsx`)

```js
import { ArrowLeft, Heading2, List, Bold, Italic, Strikethrough, Globe } from 'lucide-react';
```

Totes són de `lucide-react` (correcte). El problema visual és **semàntic de glif**: `Bold` / `Italic` / `Strikethrough` / `Heading2` són glifs tipogràfics (lletres amb serifa / “H2”), mentre la resta de la UI (Folder, List, PanelLeftClose, ArrowLeft…) és **traç geomètric** d’una sola família visual.

L’única icona **no** Lucide (IAIA a la barra negra superior) queda **fora d’abast** i no s’ha de tocar.

### 2.2 Canvis recomanats (mateixa llibreria, traç més geomètric)

| Acció | Actual | Proposta Lucide | Motiu |
|--------|--------|------------------|--------|
| Encapçalament H2 | `Heading2` | `Heading` | Glif més net, menys “H2 tipogràfic”. |
| Llista | `List` | `List` (mantenir) | Ja geomètrica. |
| Negreta | `Bold` | `Bold` **o** `Type` si es vol trencar la “B” | Si es manté `Bold`, unificar `strokeWidth={1.75}` a tota la toolbar. |
| Cursiva | `Italic` | `Italic` + mateix `strokeWidth` | No hi ha alternative geomètrica clara a Lucide sense perdre semàntica. |
| Ratllat | `Strikethrough` | `Strikethrough` **o** `Minus` + estat actiu | `Strikethrough` és el més llegible; unificar traç. |
| Tornar | `ArrowLeft` | mantenir | Coherent. |
| Publicar | `Globe` | mantenir | Coherent. |

**Pla mínim (recomanat):**

1. Substituir `Heading2` → `Heading`.
2. Forçar a **tots** els botons de la toolbar: `size={18}` i `strokeWidth={1.75}` (o 2) perquè el traç coincideixi amb Folder/List de la resta de Notes.
3. Classe CSS única `.editor-toolbar .btn-icon svg { stroke-width: 1.75; }` per no dependre de props disperses.
4. No introduir pack d’icones nou. No SVG custom per formatatge.

Això elimina la sensació de “col·leccions diferents” sense sortir de Lucide.

## 3. Pla de xoc tècnic (restauració Pedra Seca)

### P0 — Restaurar layout (bloquejant)

1. **`NotesSection.jsx`**  
   - Assegurar que el fill de `UniversalPage` no depèn de `:has()` com a única via.  
   - Afegir classe explícita al wrapper (p.ex. `notes-page-root`) i estils directes sobre ella, no només `:has(.notes-shell)`.

2. **`NotesSection.css`**  
   - Substituir `height: calc(100vh - var(--sdp-alt-negra))` per cadena flex segura:
     - Pare: `display:flex; flex-direction:column; flex:1; min-height:0`.
     - Shell: `flex:1; min-height:0; height:auto` (evitar `100vh` quan hi ha chrome WP / admin-bar).
   - Treure o condicionar `position: sticky` si el host ja fixa la barra negra.

3. **Mòbil**  
   - **Eliminar** la regla que amaga la toolbar en editor:
     ```css
     /* ESBORRAR o invertir */
     .notes-shell[data-editant="true"] .editor-toolbar { display: none; }
     ```
   - Mantenir toolbar flotant inferior en `mobile-panel-editor`.
   - En seleccionar nota: `setMobilePanel('editor')` de forma explícita a `NotesContext`.

4. **Editor**  
   - Treure `style` inline de `editorProps.attributes`; moure `min-height` / `flex` a CSS (`.editor-content`).

### P1 — Icones

1. `NotesToolbar.jsx`: import `Heading` en lloc de `Heading2`.
2. Unificar `strokeWidth` a la toolbar.
3. Revisió visual ràpida: barra negra (sistema) vs barra carbó de l’editor — mateixa família Lucide, IAIA intacta.

### P2 — Regressió

- Desktop ≥768px: 3 columnes, collapse de carpetes/llista OK.  
- Mòbil: folders → notes → editor amb toolbar visible.  
- Canvi de nota no deixa contingut TipTap d’una altra nota (ja hi ha `setContent` per `activeNote.id`).  
- Publicar no canvia layout.

## 4. Protocol d’autocorrecció de plantilles (PLANTILLA_ISO_SDP.md)

### 4.1 Problema

Una IA ha generat un prompt/petorreta **esborrant o ignorant** el format canònic de `PLANTILLA_ISO_SDP.md` sense llegir el context de la Wiki. Això és fallada de **càrrega de cànon**, no de generació de text.

### 4.2 Mecanisme (fail-closed, sense dependències noves)

**A. Regla d’agent (obligatòria abans de generar petorreta / acta / prompt)**

Afegir a `.agents/skills` o a `PROTOCOL_PETORRETA.md` / skill `socdepoble-workflow`:

1. Abans de qualsevol plantilla ISO / petorreta:
   - Llegir `PLANTILLA_ISO_SDP.md` (ruta canònica sota `_wiki_de_poble/02_ACTUAR_Maquina_Tecnica/plantilles/`).
   - Llegir el bloc fixe d’identitat + sinapsis mínimes de la plantilla.
2. Si el fitxer no existeix o el frontmatter no passa esquema → **SDP-LOCK**: no generar, informar absència.
3. Prohibit: reescriure frontmatter `tipus/estat/description` fora de l’esquema; prohibit esborrar seccions obligatòries de la plantilla.

**B. Porta mecànica (tractor)**

Extensió mínima d’un gate existent (p.ex. `tractor-frontmatter.mjs` o nou `tractor-plantilles.mjs`):

- Comprovar que `PLANTILLA_ISO_SDP.md` existeix i té les seccions capçalera obligatòries (tipus, estat, description, bloc d’identitat, tancament obligatori).
- Qualsevol generador de bundle/petorreta (`crear_bundle.mjs`, scripts de prompt) ha de **llegir** la plantilla i fallar si el cos generat no conté els marcadors estructurals (p.ex. `## Objectiu`, `## Tancament Obligatori`, ancoratge `[[00_INDEX_ESCRIPTORI]]`).
- Fail-closed: exit ≠ 0 si el prompt generat omet el format.

**C. Checklist humana / Consell (una línia al PROTOCOL_PETORRETA)**

> Abans d’acceptar una petorreta generada per IA: verificar que el cos respecta `PLANTILLA_ISO_SDP.md`. Si no, rebutjar i regenerar amb la plantilla carregada.

Això evita que “MAI MÉS” es presenti un prompt net de format sense haver llegit el cànon: la lectura + validació és **precondició**, no opció.

## 2. Avaluació DAFO
