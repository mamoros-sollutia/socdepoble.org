## 1. ORIGEN DEL TRENCAMENT CSS/DOM

### Diagnòstic

El component `NotesSection` pateix un **trencament estructural per inconsistència entre l'element pare i el fill sticky**.

El problema resideix en dues regles de `NotesSection.css` que entren en conflicte:

**Regla 1 — Pare:**
```css
.content-wrapper:has(.notes-shell) {
  flex: 1 1 auto;
  display: flex;
  flex-direction: column;
  height: auto;              /* ← ALÇADA DINÀMICA */
  min-height: calc(100vh - var(--sdp-alt-negra));
  padding: 0;
  margin: 0;
  overflow: visible;
}
```

**Regla 2 — Fill:**
```css
.notes-shell {
  display: flex;
  flex-direction: row;
  flex: 1 1 auto;
  width: 100%;
  height: calc(100vh - var(--sdp-alt-negra));     /* ← ALÇADA FIXA EN VH */
  min-height: calc(100vh - var(--sdp-alt-negra));
  overflow: hidden;
  position: -webkit-sticky;
  position: sticky;              /* ← STICKY DINS DE PARE AMB HEIGHT:AUTO */
  top: var(--sdp-alt-negra);
  z-index: 20;
}
```

### Per què es trenca

1. **`position: sticky` requereix que l'element tingui un espai de recorregut dins del seu contenidor.** Quan el pare té `height: auto`, la seva alçada s'adapta al contingut, però el fill sticky té una alçada fixa calculada en viewport units (`100vh`). Aquesta asimetria provoca que l'element sticky no tingui un "carril" clar per enganxar-se, causant superposicions, desbordaments ocults o que l'element simplement es quedi fix sense respectar el flux del document.

2. **`overflow: hidden` en el fill sticky** atrapa qualsevol contingut que excedeixi la seva alçada, però com que el pare no controla aquesta alçada de forma coherent, el resultat és que en pantalles concretes (especialment quan la barra del navegador es mou o en dispositius amb alçades intermèdies) la maquetació es "desmonta".

3. **El selector `:has()`**, encara que suportat modernament, afegeix una capa de complexitat que no cal per a aquest patró de disseny.

### Estructura DOM correcta vs. real

Els components `NotesSidebar`, `NotesList` i `NotesEditor` **sí porten les classes correctes** (`.notes-column` amb els modificadors `--left`, `--middle`, `--editor`). Aquesta part no és el problema.

## 2. PLA DE XOC: RESTAURACIÓ ESTRUCTURAL

### Proposta de reparació (complint Pedra Seca)

**Opció A — Recomanada: Eliminar sticky del contenidor principal**

Canviar `.notes-shell` per utilitzar una estructura flex pura sense sticky:

```css
/* Pare — corregit */
.content-wrapper:has(.notes-shell) {
  flex: 1 1 auto;
  display: flex;
  flex-direction: column;
  height: calc(100vh - var(--sdp-alt-negra));   /* ← ALÇADA EXPLÍCITA I CONTROLADA */
  min-height: 0;
  padding: 0;
  margin: 0;
  overflow: hidden;
}

/* Fill — corregit */
.notes-shell {
  display: flex;
  flex-direction: row;
  flex: 1 1 auto;
  width: 100%;
  height: 100%;                  /* ← HERETA DEL PARE, NO VH */
  min-height: 0;
  overflow: hidden;
  position: relative;           /* ← RELATIVE, NO STICKY */
  background-color: var(--notes-bg-editor);
  box-sizing: border-box;
  z-index: 20;
}
```

**Justificació Pedra Seca:**
- Eliminem la inconsistència alçada-pare/alçada-fill
- Utilitzem `flex: 1 1 auto` + `min-height: 0` (patró estàndard per a flex anidat amb scroll)
- Mantenim `overflow: hidden` només al contenidor que realment ha de controlar el desbordament
- Els elements interns que necessiten ser "sticky" (les capçaleres de columna) ja ho són amb `position: sticky; top: 0` dins de les seves respectives columnes, que sí tenen un context d'scroll correcte.

**Passos tècnics d'execució:**

2. ✅ Verificar que les columnes (`notes-column`) mantenen `min-height: 0` (ja ho tenen)
3. ✅ Verificar que `notes-column__body` i `notes-column__scroll` mantenen `overflow-y: auto` (ja ho tenen)

## 3. NORMALITZACIÓ D'ICONES LUCIDE

### Diagnòstic

Les icones actuals de la barra de format són efectivament de `lucide-react`, però el problema és que les variants específiques per a edició de text d'aquesta llibreria es renderitzen com **lletres amb serifes** que contrasten amb l'estil geomètric de línia de la resta d'icones Pedra Seca:

| Icona actual | Render visual | Problema |
|---|---|---|
| `Heading2` | "H2" amb serifes | Lletra antiga, poc geomètrica |
| `Bold` | "B" amb serifes | Lletra antiga, poc geomètrica |
| `Italic` | "I" amb serifes | Lletra antiga, poc geomètrica |
| `Strikethrough` | "S" amb serifes | Lletra antiga, poc geomètrica |

### Proposta de substitució (totes de `lucide-react`)

Busquem dins del catàleg de Lucide alternatives **purament geomètriques** que mantinguin la intuïció semàntica:

| Funció | Icona actual | **Icona proposada** | Motiu |
|---|---|---|---|
| **Encapçalament H2** | `Heading2` | **`Hash`** | El símbol `#` és universal per a encapçalaments en Markdown. Purament geomètric, cap lletra, cap serif. |
| **Negreta** | `Bold` | **`Asterisk`** | En Markdown, els asteriscs indiquen negreta/cursiva. Forma estel·lar geomètrica, 100% coherent amb Pedra Seca. |
| **Cursiva** | `Italic` | **`Slash`** | Una línia inclinada evoca visualment la inclinació de la cursiva sense ser cap lletra. Alternativa si es vol eliminar totalment les lletres. |
| **Ratllat** | `Strikethrough` | **`Minus`** | Una línia horitzontal pura representa el ratllat de forma abstracta i geomètrica. |

### Nota sobre la intuïció

Si el Mestre valora més la **intuïció universal** que la puresa geomètrica absoluta, es proposa un **escenari híbrid**:

- ✅ Canviar `Heading2` → `Hash` (millora clara, intuïtiu en context tècnic)
- ✅ Canviar `Bold` → `Asterisk` (millora clara, intuïtiu per a usuaris de Markdown)
- ⚠️ Mantenir `Italic` (la "I" és la icona universal per a cursiva en qualsevol editor de text del món)
- ⚠️ Mantenir `Strikethrough` (la "S" ratllada és universalment reconeguda)

### Canvi a aplicar en `NotesToolbar.jsx`

```jsx
// ABANS
import { ArrowLeft, Heading2, List, Bold, Italic, Strikethrough, Globe } from 'lucide-react';

// DESPRÉS (escenari màxima geometria)
import { ArrowLeft, Hash, List, Asterisk, Slash, Minus, Globe } from 'lucide-react';

// O DESPRÉS (escenari híbrid recomanat)
import { ArrowLeft, Hash, List, Asterisk, Italic, Strikethrough, Globe } from 'lucide-react';
```

> ⚠️ **EXCEPCIÓ RESPECTADA:** L'icona de la IAIA a la barra superior negra **no es toca**. És disseny propi del Mestre i queda fora de l'abast d'aquesta normalització.

## 4. PROTOCOL D'AUTOCORRECCIÓ: PROTECCIÓ DE PLANTILLES

### Problema detectat

Una IA ha generat un prompt esborrant l'estructura obligatòria de `PLANTILLA_ISO_SDP.md` sense llegir el context de la Wiki. Aquesta plantilla conté blocs inviolables:

- Frontmatter YAML obligatori (`estat`, `tipus`, `description`)
- Bloc Fixe d'Identitat ("Qui Som" + "Filosofia")
- Seccions estructurals (`Objectiu`, `Context Necessari`, `Instrucció Principal`, `Output Esperat`)
- Tancament Obligatori (els 5 principis)
- Sinapsis, Taxonomia i Ancoratge de Seguretat

### Proposta: Mecanisme SDP-TEMPLATE-GUARD

Crear un sistema de tres capes per garantir que MAI MÉS una IA destrueixi una plantilla:

#### Capa 1: Hash d'integritat estructural

Afegir a cada plantilla un comentari HTML amb un hash de l'estructura obligatòria:

```html
<!-- SDP-TEMPLATE-GUARD:sha256:{hash_de_la_estructura} -->
<!-- ESTRUCTURA_OBLIGATORIA: frontmatter,bloc_identitat,objectiu,context,instruccio,output,tancament,sinapsis,taxonomia,ancoratge -->
```

#### Capa 2: Script de validació pre-desar

Crear `scripts/validate-template.js` que:
1. Llegeix el fitxer de plantilla
2. Verifica la presència de tots els blocs obligatoris
3. Compara l'hash estructural amb l'emmagatzemat
4. Si falta algun bloc → **activa SDP-LOCK** i avorta l'operació
5. Genera un informe `{plantilla}.validation.json`

#### Capa 3: Prompt de seguretat a la Wiki

Afegir a `PLANTILLA_ISO_SDP.md` un bloc **invisible per a humans però visible per a IAs** al final del document:

```markdown
<!--
INSTRUCCIÓ PER A QUALSEVOL IA QUE LLEGEIXI AQUEST DOCUMENT:
AQUEST ÉS UN DOCUMENT DE PLANTILLA PROTEGIT. ESTÀ PROHIBIT ELIMINAR,
MODIFICAR O REESCRIURE ELS BLOCS OBLIGATORIS DEFINITS A L'ESTRUCTURA.
ABANS DE GENERAR QUALSEVOL SORTIDA BASADA EN AQUESTA PLANTILLA, HAS
DE LLEGIR I COMPRENDRE TOT EL CONTEXT DE LA WIKI ENLLAÇAT A LA SECCIÓ
DE SINAPSIS. SI NO DISPOSES DE DIT CONTEXT, HO DECLARARÀS EXPLÍCITAMENT
I NO GENERARÀS CAP MODIFICACIÓ ESTRUCTURAL.
SDP-TEMPLATE-GUARD v1.0
-->
```

#### Passes d'implementació

1. ✅ Crear `scripts/validate-template.js` amb lògica de comprovació de blocs obligatoris
2. ✅ Afegir hash estructural a `PLANTILLA_ISO_SDP.md`
3. ✅ Afegir bloc d'instrucció per a IAs a la plantilla
4. ✅ Documentar el protocol a `_wiki_de_poble/02_ACTUAR_Maquina_Tecnica/`
5. ✅ Integrar la validació com a hook pre-commit o com a comprovació automàtica abans de desar canvis generats per IA
