## 1. RESUM EXECUTIU

### Valoració Global: **8.2 / 10 — Sòlid amb deute tècnic controlat**

La versió 1.4.0 representa un **salt arquitectònic madur** des de l'Offline-First original fins a un model **Online-First estricte** amb enxufabilitat per a Sollutia. Les decisions clau són sòlides:

✅ **Encerts majors:**
- Preact via `react/compat` (≈3KB en lloc de ≈42KB de React)
- Build dual: Web (ESM + PWA) + WordPress Standalone (ESM pur, `type=module`)
- Sistema de **Tractors/Portes** com a govern mecànic immutable
- Custom Element `<soc-de-poble>` com a contracte d'integració ferm
- Host.js separant configuració i segellat en dues fases
- Supabase com a font única de veritat
- SDP-LOCK com a mecanisme de seguretat per a operacions perilloses

⚠️ **Deute tècnic significatiu però categoritzat:**
- **165 classes CSS òrfenes** + **69 classes no referenciades** = bloat visual
- **99 fitxers** amb estils en línia (contra la Llei Pedra Seca 03)
- **258 classes "forasteres"** fora del vocabulari de disseny
- **4 errors de seguretat Sollutia** pendents (RLS, JWT en localStorage, cua offline)
- **9 promeses P2** al tooling amb degradació silenciosa d'errors

### 2.2 Mecanisme d'Arrencada (Arquitectura Inversa)

**Abans (260830−):** `main.jsx` cridava `defineCustomElement()` directament, segellant el backend sense finestra per a injecció.

**Després (1.4.0):** Patró de dues fases via `host.js`:

1. **Fase 0 — Càrrega:** S'exposa `window.SocDePoble` global amb mètode `configura()`
2. **Fase 1 — Configuració:** Host (Sollutia/WordPress) pot injectar implementació pròpia
3. **Fase 2 — Segellat:** `arrencaAuto()` al següent `microtask` congela la configuració via `Object.freeze()`
4. **Fase 3 — Muntatge:** Es defineix `<soc-de-poble>` i s'instancia al DOM

Aquest patró és **excel·lent**: garanteix agnosticisme del backend, evita injeccions tardanes i manté retrocompatibilitat (si ningú configura, usa Supabase per defecte).

### 2.3 Build Dual: Web vs WordPress Standalone

| Característica | Build Web (`vite.config.js`) | Build WP (`vite.standalone.config.js`) |
|---|---|---|
| **Target** | ES2020 | ES2019 (Baseline 2022 · iPad A10) |
| **Format** | Aplicació ESM | Llibreria ESM pura (`lib`) |
| **Entry** | `src/main.jsx` | `src/wp-standalone.js` |
| **PWA** | ✅ `vite-plugin-pwa` autoUpdate | ❌ (no té sentit en incrustació) |
| **CSS** | Code-Split habilitat | `cssCodeSplit: false` (un sol arxiu) |
| **Output** | `dist/` | `wordpress-plugin/dist/` |
| **Dynamic Imports** | Habilitats | `inlineDynamicImports: false` → chunks separats |

**Valoració:** El build standalone és **molt ben pensat** per a l'objectiu WordPress:
- `target: es2019` assegura compatibilitat iPad A10 Fusion (iOS 15+, Safari 15+)
- Format ESM permet `<script type="module">` sense globals pol·lutors
- CSS sense splitting garanteix un sol asset per enganxar
- Chunks dinàmics permeten càrrega diferida de seccions grans

### 2.4 Capa de Dades: El Contracte `backendPort.js`

El sistema implementa el patró **"Terminal Estúpid"**:
- El frontend **no sincronitza res** localment amb lògica de negoci
- Envia operacions, rep respostes
- Si falla: delega o reverteix UI (rollback pessimista)
- El backend s'injecta via `host.js` i es `freeze` abans de muntar

Aquesta decisió (extirpació de l'Offline-First, Agost 2026) és **arquitectònicament correcta** per a Sollutia: evita "optimisme tòxic" que podria injejar dades inconsistents en sistemes externs. El preu a pagar és menor resiliència en xarxes febles, però el context rural ho accepta a canvi de sobirania de dades.

| `tractor-doctrina.mjs` | Comprova la doctrina del codi |
| `tractor-pedra-seca.mjs` | Aplica les lleis de Pedra Seca al codi |
| `tractor-rutes.mjs` | Valida rutes i literals orfes |
| `tractor-vocabulari.mjs` | Comprova el vocabulari de classes CSS |

**Valoració:** ⭐⭐⭐⭐⭐ (5/5)

## 4. VALORACIÓ CRÍTICA DETALLADA

### 4.1 Rendiment

✅ **Positiu:**
- Preact en lloc de React: estalvi de ≈39KB de JS inicial
- Vite 7 + ESBuild: build ràpid, HMR excel·lent
- Code-Splitting per routes: càrrega inicial més lleugera
- Target ES2019/ES2020: sintaxi moderna sense polyfills pesats
- PWA amb Workbox: caché intel·ligent per a visites repetides

⚠️ **Àrees de millora:**
- **CSS Bloat:** 69 classes òrfenes + 165 classes sense referència al Pedra Seca = aproximadament 15-25% del CSS és inútil
- **Estils en línia (99 fitxers):** No són "pesats" per se, però impedeixen que el navegador cachegi regles CSS reutilitzables
- **Umami Analytics:** S'envia des de CDN extern (eu.umami.is) sense `preconnect`; afegir `<link rel="preconnect">` reduiria el temps de connexió

### 4.2 Cohesió Arquitectònica

✅ **Fort:**
- **Contracte ferm:** `backendPort.js` + `host.js` defineixen una interfície clara
- **Custom Element:** `<soc-de-poble>` encapsula tot el sistema; WordPress només veu una etiqueta HTML
- **Build dual coherent:** Mateix codi font, dues sortides optimitzades per a cada entorn
- **Govern mecànic:** Les portes són part del build; no es pot saltar-se la qualitat

⚠️ **Feble:**
- **Discrepància de versions:** `package.json` diu `1.0.0` però el sistema SDP és `1.4.0`. Pot confondre nous desenvolupadors.
- **CSS en transició:** Hi ha evidència de migració parcial: classes `sdp-*` (nou sistema) mezclades amb classes BEM sense prefix (antic sistema) + classes de tipus Tailwind (`text-danger`, `text-muted`, `text-white`)
- **Tokens fantasma:** 7 variables CSS definides però no utilitzades, indicant una migració de tokens incompleta

### 4.3 Seguretat

✅ **Bones pràctiques:**
- Relé OAuth amb llista blanca d'orígens per **igualtat exacta** (no `startsWith`, no regex)
- DOMPurify per a contingut HTML generat per usuaris
- `Object.freeze()` de la configuració abans de muntar
- SDP-LOCK per a operacions perilloses
- Supabase RLS com a primera línia de defensa

⚠️ **Riscos pendents (extrets de `.sollutia-deute.json`):**
1. **🔴 JWT en localStorage:** Vulnerable a XSS. Recomanació: `HttpOnly` cookies o memòria en RAM amb refresh
2. **🟠 RLS per tenant incompleta:** Risc de filtrat de dades entre pobles/tenants
3. **🟡 Manca cua offline RuralSyncQueue:** Operacions d'usuari en xarxa feble es perden
4. **🟡 Integració PowerSync/ElectricSQL pendent:** La sobirania local continua sent una meta

## 5. PROPOSTES DE MILLORA CONTÍNUA

Ordenades per **prioritat · impacte / esforç**.

### 🔴 PRIORITAT ALTA (Seguretat i Arquitectura)

**P-01: Migrar JWT de localStorage a HttpOnly cookie**
- **Problema:** XSS pot robar sessió
- **Solució:** Backend Supabase amb custom cookie endpoint o usar `supabase.auth.setSession()` en memòria només
- **Esforç:** Mitjà · **Impacte:** Seguretat crítica

**P-02: Completar RLS per tenant**
- **Problema:** Dades entre tenants poden filtrar-se
- **Solució:** Revisar totes les policies de Supabase, assegurar `tenant_id` en cada query
- **Esforç:** Mitjà · **Impacte:** Seguretat de dades multi-tenant

**P-03: Eliminar classes de tipus Tailwind residuals**
- **Problema:** `text-danger`, `text-muted`, `text-white` contaminen el sistema Pedra Seca
- **Solució:** Reemplaçar per equivalents `sdp-text-*` o tokens de disseny
- **Esforç:** Baix · **Impacte:** Cohesió del sistema de disseny

**P-04: Unificar la numeració de versions**
- **Problema:** package.json 1.0.0 vs SDP 1.4.0
- **Solució:** Fer que `package.json` reflecteixi la versió del sistema, o documentar clarament la distinció
- **Esforç:** Molt baix · **Impacte:** Claredat per a nous desenvolupadors

### 🟠 PRIORITAT MITJA (Rendiment i Mantenibilitat)

**P-05: Neteja massiva de CSS orfe**
- **Problema:** 234 classes sense ús (165 + 69)
- **Solució:** Utilitzar `.estucat-deute.json` i `.pedra-seca-deute.json` com a guia; eliminar per lots
- **Esforç:** Alt però mecànic · **Impacte:** Reducció bundle CSS ≈20%

**P-06: Extreure colors crus a tokens**
- **Problema:** 30 colors hardcodejats impedeixen theming
- **Solució:** Crear variables CSS a `design-tokens.css`, reemplaçar usos
- **Esforç:** Mitjà · **Impacte:** Habilita mode fosc, adaptació per marques de clients Sollutia

**P-07: Convertir estils en línia a classes**
- **Problema:** 99 fitxers amb `style={{}}`
- **Solució:** Per lots, moure regles a classes CSS reutilitzables; començar pels components més compartits
- **Esforç:** Alt · **Impacte:** Millora caché del navegador, coherència visual

**P-08: Preconnect per a Umami**
- **Problema:** Carrega analítica sense connexió prèvia
- **Solució:** Afegir `<link rel="preconnect" href="https://eu.umami.is">` a `index.html`
- **Esforç:** Molt baix · **Impacte:** Millora LCP/Performance

### 🟡 PRIORITAT BAIXA (Qualitat de Vida i Futur)

**P-09: Arreglar les 9 promeses P2 al tooling**
- **Problema:** Errors silenciosos degradats a "avisos"
- **Solució:** Convertir `console.warn` en `throw` o, com a mínim, `console.error` amb codi de sortida no zero en mode CI
- **Esforç:** Baix · **Impacte:** Robustesa del sistema de portes

**P-10: Definir la cua RuralSyncQueue**
- **Problema:** Operacions en xarxa feble es perden
- **Solució:** Implementar una cua en IndexedBB que reintenti operacions quan hi ha xarxa; mantenir Online-First però amb "buffer de cortesia"
- **Esforç:** Alt · **Impacte:** Millora experiència rural

**P-11: Eliminar accessos globals**
- **Problema:** 13 accessos directes a `document.body`, `document.head`, `document.documentElement`
- **Solució:** Utilitzar refs de Preact o portals encapsulats
- **Esforç:** Mitjà · **Impacte:** Millora testabilitat, prepara per a futura SSR

**P-12: Convertir literals de ruta a constants**
- **Problema:** 81 literals orfes al tooling
- **Solució:** Crear `tooling/lib/constants.mjs` amb rutes canòniques
- **Esforç:** Baix-Mitjà · **Impacte:** Refactoring més segur

## 6. SOBIRANIA LOCAL I EL FUTUR

El sistema actual és **Sollutia-first per necessitat**, però l'arquitectura preserva la ruta cap a la sobirania:

1. **El contracte `backendPort.js`** ja abstrau el proveïdor de dades; canviar Supabase per un backend propi només requereix una nova implementació del contracte
2. **El Custom Element** manté l'UI independent del host
3. **El mode `seed`** de dades permet funcionar sense backend per a demos i desenvolupament

**La trajectòria és correcta:** Online-First ara per a estabilitat i Sollutia, però amb les portes obertes per a la sobirania local quan el projecte tinga els recursos per a mantindre un backend propi.

## 7. CONCLUSIÓ — VALORACIÓ FINAL MARIA

> 🛡️ **El sistema SDP 1.4.0 és una obra de pedra seca ben construïda sobre un sòlid fonament de govern mecànic.**

Les decisions arquitectòniques són **coherents i defensables**:
- Preact via compat és un truc intel·ligent que dona accés a l'ecosistema React amb el pes de Preact
- El patró host.js + segellat és una solució elegant per a l'enxufabilitat Sollutia
- El sistema de Tractors/Portes converteix filosofia en codi executable — això és el punt més fort del projecte

El deute tècnic existeix però **està controlat i categoritzat**. No és un sistema que es desmoroni; és un sistema que s'ha expandit fins als límits de les seves pròpies regles. La propera gran fita ha de ser una **"operació neteja"** que baixi els comptadors de deute per donar marge de creixement.

**Recomanació:** Procedir amb les millores d'alta prioritat (seguretat) immediatament, i planificar una "setmana de neteja" cada 3 versions per mantenir el sistema dins dels límits Pedra Seca sense bloquejar l'innovació.
