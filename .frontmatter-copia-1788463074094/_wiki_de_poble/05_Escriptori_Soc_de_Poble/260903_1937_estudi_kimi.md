# 🏛️ AUDITORIA FORENSE — CONSELL DE LA PETORRETA
## Informe d'Avaluació Global del Sistema `socdepoble.org`

### 1. NOTA BASE: **6.5 / 10**

**Justificació quirúrgica:** L'esquelet arquitectònic és **sòlid com una barraca de pedra seca ben feta**: només 6 dependències de runtime, zero frameworks CSS invasius, i una filosofia local-first coherent. Però el **parament** (CSS, bundle, context) està carregat de llast que farà patir l'iPad A10 com una mula pujant el Puig Campana. És un castell amb fonaments de roca i parets d'adobe saturat.

---

### 2. DIAGNÒSTIC PER FRONTS

#### 🔴 FRONT HTML SKELETON (`index.html`) — Estat: **ACCEPTABLE**
- **El bo:** Meta viewport correcte, charset UTF-8, Vite injecta el mòdul.
- **El dolent:** Inline style + script d'Umami bloquegen la cadena de crítica de render. Falta `link rel="manifest"` explícit per a PWA (Vite pot no injectar-lo sempre). No hi ha preconnect ni dns-prefetch a orígens externs.
- **Veredicte:** No és el coll d'ampolla principal, però podria guanyar ~200ms de FCP amb un `defer` al script d'analítica i precarrega del primer CSS crític.

#### 🔴 FRONT CSS (`src/css/index.css`) — Estat: **CRÍTIC / MONOLÍTIC**
Aquest és el **elefant a l'habitació**. Dades forenses:
- **112 KB** en un sol fitxer. 3.249 línies. Això en un iPad A10 amb xarxa rural 3G/4G és un **tret al peu**.
- **26 `!important`** — Guerra d'especificitat declarada. Això no es manté, esdevé foscor.
- **55 `box-shadow`**, **72 `transform`** — Efectes GPU que en un A10 (PowerVR Series 7XT) consumiran bateria i causaran frame drops.
- **1 `@import`** — Bloqueja la cadena de crítica de render. No pot haver-hi imports sincrònics en CSS de producció.
- **12 KB en comentaris** — Pes mort que no aporta res al runtime.
- **Cap splitting per ruta** — Tot el CSS es carrega encara que l'usuari només vaja al Login.

#### 🔴 FRONT REACT (`App.jsx` + `AppDataContext.jsx`) — Estat: **DOLENT**
- **App.jsx:** 8 `useEffect` sense `useMemo`/`useCallback`. Cada canvi d'estat re-renderitza tot l'arbre. En un A10, això es nota com a "enganxades" de UI.
- **AppDataContext.jsx:** 23 KB de context global amb **8 Providers anidats**. Això és "Provider Hell". Quan canvia qualsevol valor, tots els consumidors es re-renderitzen. No hi ha `useReducer` ni separació de contexts per domini.
- **Sense `React.lazy` ni `Suspense`** — Tota l'aplicació es descarrega de cop. En una PWA rural-first, això és inacceptable.
- **DesignSection.jsx (63 KB)** i **UniversalComponents.jsx (45 KB)** — Monolits que embruten el bundle. El "Storybook vivent" no pot anar a producció sencer.

#### 🟡 FRONT TOOLING (`vite.config.js`) — Estat: **INSUFICIENT**
- **Sense code splitting configurat** — `manualChunks` no existeix. Rollup empaqueta tot en un sol JS.
- **Sense optimització de CSS** — No hi ha `cssCodeSplit`, ni purga, ni `build.cssMinify`.
- **Target `es2020`** — Correcte per a baseline 2022, però es podria afinar.
- **El bo:** Alias `@/` configurat, server amb watch intel·ligent.

#### 🟢 FRONT DEPENDÈNCIES (`package.json`) — Estat: **EXCEL·LENT**
- **6 dependencies de runtime.** Això és pura orquestra. Zero lodash, zero moment, zero jQuery, zero Tailwind. Respecte absolut a la doctrina Pedra Seca.
- **14 devDependencies** — Raonable. Husky, ESLint, Vitest... toolchain sana.
- **Anomalia:** `react` i `react-dom` estan a `devDependencies`. Haurien de ser `dependencies` (affects npm install --production).

### 4. RECOMANACIONS QUIRÚRGiques (Amb Imaginació Analítica)

#### Opció A: **La Cura d'Emergència** (1 setmana, baix risc)
1. **Trencar el CSS monolít** en 3 fitxers: `critical.css` (primer render, <15KB), `components.css` (lazy per ruta), `editorial.css` (textos llargs).
2. **Afegir `React.lazy` + `Suspense`** a `App.jsx` per a cada secció de `/src/sections/*/`.
3. **Moure `react` a `dependencies`**.
4. **Eliminar comentaris CSS** en build via Vite (ja ho fa però, però verificar).
5. **Resultat esperat:** FCP reduït un 40-50%, nota pujaria a **7.5/10**.

#### Opció B: **La Refundació del Context** (2-3 setmanes, risc mitjà)
1. **Fragmentar `AppDataContext`** en contexts per domini: `AuthContext`, `DataContext`, `UIContext`, `NotesContext`. Que cada un siga consumit només on calga.
2. **Implementar `useReducer`** per a estats complexos (notes, xat, mercat).
3. **Aplicar `React.memo`, `useMemo`, `useCallback`** a `App.jsx` i components de llista.
4. **Extraure `DesignSection.jsx`** com a ruta independent `/disseny` que no es carregui en producció (o protegida per flag).
5. **Resultat esperat:** Eliminació de re-renders en cascada, app fluida en A10. Nota **8.5/10**.

#### Opció C: **La Gran Muralla** (1-2 mesos, visió estratègica)
1. **Adoptar CSS Layers (`@layer`)** per eradicar la guerra d'`!important` i establir prioritats declaratives.
2. **Implementar "Island Architecture"** — Components estàtics prerenderitzats, només hidratar els interactius.
3. **Service Worker amb estratègia "Cache then Network"** per a assets estàtics, i "Network first" per a dades de Supabase.
4. **Purgar CSS no usat** amb `purgecss` o `lightningcss` en pipeline de build.
5. **Resultat esperat:** PWA d'elit, offline real, nota **9.5/10**.

### 6. DADA D'APRENENTATGE (Mètode Humà)

> **Lliçó extreta:** Un projecte amb 6 dependències i una filosofia neta pot tenir igualment el coll d'ampolla en el propi codi. La "puresa" no està en el nombre de `node_modules`, sinó en com es reparteix el pes entre el que l'usuari necessita **ara** i el que pot esperar **després**. El CSS de 112KB és la prova que la disciplina en el `package.json` no es va traslladar al `index.css`. És com tenir un mas impecable per fora i l'almàssera plena de ferralla.
