Pedra Seca restaurada

S'han restaurat les 3 barres superiors i el peu de targeta a UniversalComponents.jsx i Cards.jsx. API neta de presentació basada en props booleanes: zero callbacks fantasma, zero divs innecessaris.

01 · Diagnòstic quirúrgic

ABANS · Codex netejant

En purgar callbacks inerts, Codex va eliminar la representació visual de:

  • ✗ header.bar-black
  • ✗ header.bar-blue
  • ✗ section.bar-orange
  • ✗ footer.sp-card-footer (hora · pin · traduir · comentar · compartir · connectar)
Arrel: if (!onClick) return null a IconButton. Sense callback, no es pinta res. El Design System es quedava calvari.
DESPRÉS · API neta

Nova capa de maneres de presentació. El component decideix pintar per props booleanes, no per l'existència d'un handler:

  • ✓ showBarBlack / showBarBlue
  • ✓ showBarOrange / hasFooter
  • ✓ showTranslate · showComment · showShare
  • ✓ showPin · showDateTime · showConnect
Resultat: () ={'>'} {} desapareix completament de Cards.jsx.

Si es passa un onClick el botó és operatiu. Si només hi ha la prop booleana, el botó és presentacional i apareix disabled. La decisió de pintar i la decisió de fer estan separades.

05 · Preparació WordPress · socdepoble.cat

L'API de props booleanes + JSON-serialitzables és directament injectable des de PHP. Cada component es pot embolcallar en un Custom Element (Web Component) que llegeix atributs i muntar el React allà dins. Sense fricció.

1. Shortcode PHP

Atributs del shortcode → props JSON → atribut data-props del Web Component.

2. Custom Element

connectedCallback llegeix atributs, crea arrel React i injecta UniversalCard amb les props.

3. Shadow DOM

CSS aïllat del tema WP. Les variables --sdp-* es propaguen i són overridables.

Efecte inmediat: el plugin WP només ha de registrar [sdp_card showPin hasFooter showTranslate ...]. El component és el mateix a React, al Design System i a WordPress — una sola font de veritat.
